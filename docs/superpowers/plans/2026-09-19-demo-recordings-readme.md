# Deterministic Demo Recordings and README Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add reproducible eight-second recordings and animated README previews
for all six web playground scenes.

**Architecture:** A repository-owned TypeScript CLI drives the existing
Playwright Chromium with a synthetic animation-frame clock, captures numbered
PNG frames from `.player-panel`, and passes those frames to fixed `ffmpeg`
encoders. Pure configuration and artifact helpers are unit-tested separately
from browser capture. Generation validates a complete temporary output,
records tool and content hashes in a canonical manifest, and transactionally
updates `docs/assets/demos/`; check mode compares generated bytes without
changing committed files.

**Tech Stack:** Bun 1.4.2, TypeScript 7.0.2, Playwright 1.63.0 Chromium, Vitest
5.0.1, Vite 8.3.0, FFmpeg/FFprobe 8.1.1 capture profile, Markdown, `just`.

## Global Constraints

- Capture all six canonical scene IDs in catalog order.
- Each clip represents exactly 480 engine steps: eight seconds at 60 Hz.
- Capture 240 output frames at 30 fps, one PNG after each pair of engine steps.
- Use a fixed 1280×960 viewport and device scale factor 1.
- Trigger one scene-specific pointer interaction after engine step 180.
- Capture `.player-panel`, excluding volatile footer build provenance.
- Generate silent H.264 MP4 and animated WebP files.
- Store committed output under `docs/assets/demos/`.
- Generate into a temporary directory and preserve the prior committed
  directory on every failure.
- Same-profile reruns must produce identical SHA-256 hashes and no git diff.
- Cross-platform byte identity is not claimed; record platform, Chromium, and
  FFmpeg identities in the manifest.
- Production physics and rendering code must not gain capture-only behavior.
- Preserve unrelated `.vscode/` content and existing file-length findings.

import { describe, expect, it } from "vitest";

import { SCENE_IDS } from "../src/catalog/scenes";
import {
  CAPTURE_PROFILE,
  SCENE_CAPTURE_PLANS,
  canonicalManifestJson,
  frameFileName,
  type DemoMediaManifest,

describe("demo media capture model", () => {
  it("covers every scene once in canonical order", () => {
    // Arrange
    const expectedIds = [...SCENE_IDS];

    // Act
    const actualIds = SCENE_CAPTURE_PLANS.map((plan) => plan.id);

    // Assert
    expect(actualIds).toEqual(expectedIds);
    expect(new Set(actualIds).size).toBe(expectedIds.length);
  });

  it("defines an exact eight-second capture profile", () => {
    // Arrange

    // Act
    const representedSteps =
      CAPTURE_PROFILE.frameCount * CAPTURE_PROFILE.stepsPerFrame;

    // Assert
    expect(CAPTURE_PROFILE.simulationHz).toBe(60);
    expect(CAPTURE_PROFILE.outputFps).toBe(30);
    expect(CAPTURE_PROFILE.durationSeconds).toBe(8);
    expect(CAPTURE_PROFILE.frameCount).toBe(expectedFrameCount);
    expect(representedSteps).toBe(480);
  });

  it("sorts manifest scenes and emits one trailing newline", () => {
    // Arrange
    const manifest = {
      schemaVersion: 1,
      captureProfile: { inputSha256: "a".repeat(64) },
      scenes: [
        { id: "water-wheel", files: [] },
        { id: "dam-break", files: [] },
      ],

    // Act
    const serialized = canonicalManifestJson(manifest);

    // Assert
    expect(serialized.endsWith("\n")).toBe(true);
    expect(serialized.indexOf("dam-break")).toBeLessThan(
      serialized.indexOf("water-wheel"),
    );
  });

  it("formats zero-padded frame names", () => {
    // Arrange
    const frameIndexes = [0, 9, 239];

    // Act
    const names = frameIndexes.map(frameFileName);

    // Assert
    expect(names).toEqual([
      "frame-0000.png",
      "frame-0009.png",
      "frame-0239.png",
    ]);
  });
});

- [ ] **Step 4: Implement the synthetic clock**

In `installSyntheticAnimationClock`, call `page.addInitScript` before
navigation. Replace `requestAnimationFrame` and `cancelAnimationFrame` with an
ID-keyed queue and expose a capture controller on `window`. Its `advance`
method must copy and clear the current queue before invoking callbacks so a
callback that schedules its successor cannot execute recursively in the same
tick.

Use an internal controller shape equivalent to:

```ts
type SyntheticAnimationController = {
  readonly advance: (timestampMilliseconds: number) => number;
  readonly pendingCount: () => number;
};
```

`waitForReadyScene` must wait for:

- `main[data-scene="<scene id>"][data-playback="playing"]`
- a finite positive `data-step-index`
- one pending animation callback

It then advances once at timestamp 0 to establish the application's timing
anchor and returns the unchanged initial step.

`advanceEngineSteps` advances exactly `count` callbacks, adding one fixed
one-ULP-safe 60 Hz interval to the controller timestamp each time. Define that
interval once by applying `nextUp()` to
`1_000 / CAPTURE_PROFILE.simulationHz`, compute each callback timestamp as
`callbackCount * interval`, and fail fast if that single fixed interval ever
stops producing exactly one engine step per callback across all 480 capture
callbacks. After every callback, require exactly one successor callback and
verify the DOM step index increased by one. Do not use `waitForTimeout`.

- [ ] **Step 5: Implement directory comparison and rollback-safe replacement**

`compareOutputDirectories` recursively compares the sorted relative file list,
byte length, and SHA-256 for every file. It returns stable diagnostics such as
`missing: dam-break.mp4`, `extra: old.webp`, and
`changed: manifest.json`.

`replaceOutputDirectory`:

1. Renames the existing target to a sibling backup.
1. Renames the complete next directory to the target.
1. Removes the backup only after success.
1. If step 2 fails, renames the backup back to target and rethrows.

When target does not yet exist, rename next directly. Never delete the current
target before a validated next directory exists.
