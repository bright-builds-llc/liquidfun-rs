# Roadmap: liquidfun-rs

## Overview

v1.4 Scenario Performance improves simulation and rendering speed across all 25 current playground scenes through individual evidence-led investigations. Increased bounded memory is permitted; existing physics, deterministic ordering, controls, lifecycle and visual fidelity are preserved. Phase 34 prepares trustworthy measurement and completes an unchanged-source original campaign; Phases 35–59 investigate one catalog scene each; Phase 60 compares the whole catalog on final accepted source. Fine granularity follows these 27 natural acceptance boundaries. Initialization creates this roadmap only; it records no new benchmark or optimization result.

## Phase Details

### Shared scenario acceptance contract

Phase 34 establishes the reusable measurement/fidelity contracts; Phases 35–59 apply them separately; Phase 60 closes the complete corpus. **Requirements** fields are primary assignments only. The acceptance contract in [REQUIREMENTS.md](REQUIREMENTS.md) constrains every scenario phase without assigning a requirement twice.

- Keep the fixed catalog-order mapping below. Any future order change requires an explicit roadmap/traceability revision before the affected scene's evidence begins.
- Finish a validated all-25 original campaign on one unchanged production source/artifact set before solver, capture, ownership or rendering hot-path edits. Preserve historical Tesla evidence separately. Discovery windows in [FEATURES.md](research/v1.4-scenario-performance/FEATURES.md) are proposals; freeze witnessed action, counts, cycle boundaries, scripts and recreation epochs on original source before authoritative runs.
- Each scene independently follows fresh current-before → separate simulation and rendering profiles → one focused supported change at a time → fresh matched after → quality/canaries → independent acknowledgment. Keep the immediate accepted predecessor and original campaign references separate. Every independently claimed change has its own attributable before/after pair; inherited shared improvements do not substitute for the scene's investigation.
- Use fresh-session sequential unprofiled replicates (at least three by default), disposable runtime warmup, fixed simulation-step windows and baseline-derived repeatability/noise policy. Show variability, absolute units and explicit incomparable/failure outcomes. Diagnostic instrumentation, symbols, profiles and memory capture have separate identities and cannot become timing authority.
- Preserve actual production scene/session hooks, authored geometry, counts, materials, lifetime/emission, gravity, deterministic ordering and control/error behavior. Keep 1/60 timestep, rigid 8/3 iterations and actual particle iterations: Liquid Tumbler 61, Stacked Drip 12, Tesla Valve 4, all others 2. Preserve resolution/DPR and exact appearance; no approximations or skipped changed work.
- Every scene has its unchanged default run and full-particle workload with explicit cap, actual drawn counts, mode/backend, camera, viewport/DPR and shading identity. Fidelity covers circle-wireframe, triangle-wireframe, solid, soft-blob, contour and shaded-blob for every scene. Representative timed cases collectively cover all six modes and applicable fallbacks; Drawing times all six. Matched moving/count/color/radius-churn frames protect caches.
- Separate native release production-session advance, production WASM advance, capture/copy/parse, renderer CPU submission, optional GPU intervals and actual production-player observations. Preserve the actual direct/worker route, real RAF, product chrome, fresh-snapshot cadence and simulation progress; report input application/presentation latency and applicable worker queue/round-trip separately. Held-frame redraws, timer proxies and CPU submission cannot be renamed simulation progress, input latency or GPU/displayed FPS.
- Accept measured bounded memory increases for speed; disclose scope/availability and resource deltas. Reset/switch/disposal/visibility/error cycles retain bounded owners, exact invalidation, rollback/retry and cleanup. Unknown browser/GPU metrics are unavailable, not zero; logical allocation bytes are not measured VRAM.
- Shared changes immediately run applicable material/joint/color/count-churn/scale/ownership canaries against the immediate predecessor. Diagnose/correct material unexplained regressions before acceptance. Each retained change receives a simplification pass and relevant repository checks. Independent AI or human review records actual identity/time and exact diff/evidence digest; implementation self-approval is insufficient.
- Retain raw lightweight evidence and immutable failures under a new scenario-performance benchmark namespace. Large diagnostic archives require durable retrieval/provenance/hashes; ignored local files alone are insufficient. No percentage/FPS improvement is guaranteed. Unsupported speculative changes are reverted; an evidence-backed no-useful-safe-optimization disposition can close a scene honestly. Package publication/tags, C++ parity, mandatory Linux/dedicated-host qualification and universal public speed claims remain outside this milestone.

**Guidance applied:** Repository-local scope/authorization/review in AGENTS.md, AGENTS.bright-builds.md, standards-overrides.md, PROJECT-SCOPE.md, standards/index.md and architecture/verification standards; v1.4 [research summary](research/v1.4-scenario-performance/SUMMARY.md). Shared validated models and thin private adapters keep measurement effects outside the public engine API.

### Phase 34: Measurement Harness and Original Campaign

**Goal**: Maintainers can reproduce all 25 scenes' meaningful workloads and inspect a complete trustworthy original campaign before optimization.
**Depends on**: Phase 33 (archived catalog delivery; current 25-scene catalog is the scope)
**Requirements**: PERF-07, PERF-08, PERF-09, PERF-10, PERF-11, PERF-12, PERF-13, PERF-14, PERF-15
**Success Criteria** (what must be TRUE):

1. A versioned manifest equals the 25-ID web catalog/Rust scene allowlist; validation rejects missing, duplicate and unknown IDs, stale artifacts, changed settings/scripts/backend/DPR and source drift. Default and representative active cases have frozen witnessed phase/count checkpoints, including nonempty Drawing, actual Sparky bursts, shelf drainage and complete long cycles.
1. Maintainers can inspect separate native production-session, production WASM, capture/copy/parse, matched-frame rendering and actual-player results; capability probes demonstrate actual page/worker attribution and GPU/memory availability or explicit supported alternatives. Real RAF/control routing, new-frame cadence, simulation progress and input/worker latency have distinct units and meanings.
1. Complete original records cover every required scene/case on one unchanged production source/artifact set with at least three fresh unprofiled replicates by default, separate diagnostics, measured variability/noise acceptance and retained failed attempts. No production hot-path optimization has contaminated this campaign.
1. Maintainers can run validated fresh-before/profile/one-change/after comparators and inspect immutable identity/predecessor/original relationships; negative checks reject incomparable inputs. Semantic/hidden-state assertions, all-six-mode matched fidelity, unchanged defaults/full-particle drawn counts and collective all-six-mode/fallback timings establish reusable quality coverage.
1. Memory/resource observations identify their scope and unavailable metrics, and reset/switch/failure retention checks establish bounded ownership. An independent reviewer can inspect the complete harness diff and original evidence and acknowledge its exact digest with actual identity/time.
