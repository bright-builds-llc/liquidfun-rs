# Domain Pitfalls: v1.4 Scenario Performance

**Domain:** Behavior-preserving native Rust / production-WASM playground optimization
**Researched:** 2026-10-03
**Confidence:** HIGH for repository incidents and existing boundaries; MEDIUM for proposed all-scene detection coverage until Phase 34 freezes and validates workloads.

## Governing constraints

All 25 scenes receive individual investigation and evidence. The owner explicitly rejected fast approximate modes. Speed is the priority; measured increases in retained memory are allowed. Neither that permission nor the hobby scope permits leaks, skipped work, diluted fidelity or invented gains.

Apply `AGENTS.md`, its local guidance and independent-review policy, `AGENTS.bright-builds.md`, `standards-overrides.md`, `PROJECT-SCOPE.md`, and architecture/verification/testing/language standards. ## Concrete prior incidents to preserve

### Cache candidate CPU regression

Tesla Stage 5's first candidate, `20261002-stage5-after-01` (the initial cache candidate), passed physical/pixel checks but was rejected because CPU render submission increased. Its record identifies repeated metadata snapshot copies during changing particle counts and cache-key overhead. The second exploratory run remained variable. The accepted final comparison uses fresh `20261002-stage5-before-01` and corrected `20261002-stage5-after-03`, retaining both earlier attempts without selecting a fastest replicate. [Rejection](../../../docs/benchmarks/tesla-valve/verification/stage5-after-01-rejected.json), [investigated repeat](../../../docs/benchmarks/tesla-valve/verification/stage5-after-02-investigated.json).

The final documented submission means were 0.117→0.141 ms forward and 0.199→0.278 ms reverse; reverse replicate ranges overlapped. The record explicitly says these results do not establish a rendering speedup. A raster-layer experiment failed exact antialias checks and was replaced with native paths without weakening tolerance. [Tesla benchmark history, Stage 5](../../../docs/benchmarks/tesla-valve/README.md#stage-5-static-native-paths-and-gpu-metadata). **Confidence: HIGH, historical local evidence only.**

**Lesson for v1.4:** cache presence, fewer API calls, higher memory, passing tests and intuition are not gain evidence. Profile added validation/copy cost, count churn, stable populations, color-changing material scenes and dynamic walls. An unchanged/no-gain scene result is valid research closure; it does not justify retaining speculative code as an “optimization.” Existing historical cache code is not automatically removed by this milestone; each new candidate needs its own demonstrated rationale and measured outcome.

### Worker candidate passed timing but failed lifecycle review

Tesla `20261002-stage4-after-01` matched physical checkpoints but was rejected: an accepted control completed while hidden could leave a paused view with stale geometry after visibility restoration. Corrected source received a fresh after run against accepted Stage 3. [Worker rejection](../../../docs/benchmarks/tesla-valve/verification/stage4-after-01-rejected.json), [history](../../../docs/benchmarks/tesla-valve/README.md#stage-4-live-simulation-worker). **Confidence: HIGH.**

The current regression surface includes `web/tests/worker-control-races.test.ts`, `worker-session.test.ts`, `scene-lifecycle-worker.test.ts`, `frame-loop-worker.test.ts`, `worker-messages.test.ts`, and `web/e2e/live-worker.spec.ts`. Preserve hidden completion and visible redraw without another step, latest mutation wins, abandoned generation suppression, accepted work completing through pause, pending Play intent, queue overflow, late initialization, idempotent disposal and recoverable gravity rejection. Timing and checkpoint agreement do not replace these assertions.

### Source identity and runtime identity are separate

Tesla source manifests bind revision plus dirty/untracked content and artifact hashes. A later containing commit is not the report's producer revision; neither should be silently rewritten. Renderer/backend/environment agreement is also necessary for comparable timing. Preserve failed/rejected reports and exact links rather than inventing a clean passing history. [Source/evidence history](../../../docs/benchmarks/tesla-valve/README.md#source-and-evidence-commits), `web/scripts/bench-tesla/{identity,validation,results,compare}.ts`. **Confidence: HIGH.**

## Workload lifecycle traps

| Workload family | Why a universal short window fails | Freeze / verify |
| --- | --- | --- |
| Empty and interactive construction | Drawing starts empty. Brush stamps destroy overlapping particles before appending; action count is not population | Step-indexed down/move/up/cancel scripts, world coordinates and material changes; actual occupancy envelope; separate insertion and dense simulation/render windows |
| Drop/impact then settle | Warmup can discard contact creation and expensive initial solve; late calm state is cheaper | Runtime-warm disposable session, reset, then include original impact plus settled window; same seed/input/checkpoints |
| Emitters and drains | Startup count, saturated count, stop/restart and deletion/permutation use different hot paths | Frozen rate/direction/startup/steady/churn windows; actual particle counts and drain/emission checkpoints, not a cap as assumed occupancy |
| Cyclic mechanisms | Hydraulic cycle is 10 s; Bubbler approximately 13⅓ s; Stacked Drip approximately 14.278 s. A 10 s recording omits part of later cycles | Compute from source and freeze actual f32 phase boundaries; measure all dwell/rise/spill/descent portions and later complete cycle, with phase-specific metrics |
| Motor and moving walls | Caching “static” geometry ignores current transforms; stopped mode is not the spinning default | Default and representative speed/direction/preset cases; live stop/restart; geometry and motor checkpoints, unchanged style/transform order |
| Fine-scale and high-iteration scenes | Tumbler and Stacked Drip can dominate through authored density/substeps; shared settings are not equivalent workloads | Keep actual per-scene dt/iterations/particle size/fill, camera and physical scale; portrait/desktop/DPR as separate cases |
| Recreating presets / live controls | Rebuild resets scene and step index; live change continues existing ownership/state | New epoch for recreation; acknowledge application before timing; ordered exact control tokens; distinguish authored default from reconstructed gravity/material settings |

## Browser and profiler boundaries

V8 documents compilation tiers, debug tier-down and Performance-recording tier-up. Opening a debugger and timing WASM can change the code running. Keep ordinary production timing separate from diagnostic sampling/trace/heap runs, record debugger/profiler flags, and do not change tiering flags to manufacture gains. [V8 compilation pipeline](https://v8.dev/docs/wasm-compilation-pipeline). CDP precise coverage prevents optimized execution; it cannot provide timing-authoritative call counts. [CDP Profiler](https://chromedevtools.github.io/devtools-protocol/tot/Profiler/). **Confidence: HIGH for documented boundaries; actual symbol fidelity remains a Phase 34 probe.**

A page CPU profile does not automatically establish worker cost. Attach the actual related worker target, retain its identity/sample range and report missing/unattributed WASM functions. [CDP Target](https://chromedevtools.github.io/devtools-protocol/tot/Target/). Do not claim Rust function attribution because a native samply profile exists or a WASM file has debug information; confirm symbol/index mapping on the exact actual package. See [STACK.md](STACK.md) for the separate native-proxy and browser instrumentation contract.

GPU elapsed queries are asynchronous and must be read after availability, with disjoint results rejected. They cover bracketed GPU commands, not CPU submission or whole displayed frames. Extension absence, context loss and invalid/pending timeouts remain explicit unavailable/invalid metrics. [Khronos WebGL2 timer-query specification, 2023 revision](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/). **Confidence: HIGH for API; host support unmeasured.** Keep fallback renderer and software/GPU identities visible; do not compare different backend results as the same workload.

Transferable ArrayBuffers move ownership and detach the sender's buffer. A large backing allocation behind a small view still exposes a larger transfer scope; the repository rejects nonzero offsets and backing lengths different from lane lengths. [HTML structured transfer](https://html.spec.whatwg.org/multipage/structured-data.html#transferable-objects), `web/src/physics/worker-messages.ts`. **Confidence: HIGH.** Any pooling/reuse optimization must preserve these ownership rules, including errors, late frames and disposal.

Worker round trip is not pure transfer latency: it combines delivery/scheduling, computation, capture, parse and main-thread validation, and starts after the client's queue waiting in current code. Time realms separately or normalize origins; raw worker `performance.now()` minus raw page `performance.now()` is invalid cross-origin arithmetic. [High Resolution Time working draft, 2026](https://www.w3.org/TR/hr-time-3/). Timer resolution and subtraction noise limit tiny residual claims. **Confidence: HIGH for semantics.**

The existing player caps catch-up at four steps and worker frame compute near a 12 ms budget; preserve that contract while reporting step admission, actual completion and clamped/deferred work. `web/src/physics/clock.ts` and `web/src/player/{frame-loop,worker-frame-loop}.ts` are local authority. New-snapshot paint submissions, display FPS, simulation steps per wall second and time to finish a fixed simulation phase are different metrics. Tesla history already records approximately 29 reverse snapshot submissions/s after its campaign; it does not support a universal 60 FPS guarantee.

## Memory and measurement confidence

Higher bounded scratch/cache capacity can be an acceptable speed tradeoff. Buffer bytes, WASM allocated capacity, JS heap/backing storage, native allocator high-water, process RSS and logical GPU texture budgets measure different scopes. Keep their labels and unavailable reasons; do not sum overlapping ArrayBuffer/WASM/heap values into invented total memory or call a texture byte formula actual VRAM.

Check repeated scene creation, recreation, reset, shrink/grow, route switch, worker disposal and context loss separately from timing. A high-water buffer retained by one live owner is different from orphaned owners/caches accumulated each switch. Record end/high-water/lifecycle deltas rather than rejecting all increased memory, and record when an instrumented allocator or heap sampling perturbs timing. Existing dhat and parent-timer records are diagnostic, not speed authority.

Cold shader/resource/WASM startup, warm stable state and scene lifecycle transitions need separate numbers. Keep setup costs visible even when warmed steady-state improves. For extremely fast kernels, zero/coarse timer readings or overlapping replicate variation mean insufficient resolution, not zero work or proven equality. Use phase totals or appropriately bounded aggregation with the same work, and retain all raw data. Do not insert synchronous GPU waits, screenshots, hashes or heap snapshots into ordinary timing spans.

Report retained/changed source, ordinary profile, backend and instrumentation settings plus raw replicate units. A candidate can produce a large native win and a neutral browser result; report both. If no behavior-preserving beneficial optimization is found, record investigated functions, profiles, attempted/rejected proposals, fresh after/no-change observation and limitations. Do not add speculative code merely to satisfy a per-scene checklist.
