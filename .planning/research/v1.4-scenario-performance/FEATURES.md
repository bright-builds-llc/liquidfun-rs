**Domain:** Behavior-preserving optimization of all current LiquidFun playground scenarios
**Researched:** 2026-10-03

## Deterministic input scripts and warmup contract

Runtime warmup and scene-state warmup are different features. Load/compile the WASM module, initialize the renderer and exercise paths on a disposable session; reset to a fresh world before an initial-impact or creation case. A later-state case advances ordinary untimed fixed steps to the declared starting index. Native headless uses the same construction and ordered actions. Profiler runs repeat that same trajectory separately and are labeled diagnostic, never used as the speed authority.

Store input commands as `(stepIndex, sequence, operation, exact arguments)`. Apply same-step commands in stable order before advancing the next step. Pointer operations include down/move/up/cancel explicitly; browsers transform frozen world coordinates through the current camera, record actual dispatch/application order, and validate the applied checkpoint. A frame with multiple steps must not silently postpone an interaction past its intended index. Controls that recreate reset the index and require a new epoch; live controls retain the epoch. Keep source/parser-accepted tokens (`wave-speed=1.0`, `platform-width=0.92`, `platform-amplitude=0.168`), not imprecise UI labels. Freeze exact numeric/float representation, generator version and any seed; current deterministic scene constructors do not justify claiming a seed was used.

Concrete drawing recipe candidate: at step60 send down at `(-3.2,4.8)`; for `i=1..120` send move at `(-3.2+6.4*i/120,4.8)` once per step; up at the last point; repeat descending rows y=4.2,3.6,3.0,2.4 with alternating direction and fixed spacing. Separate water, elastic and material-switch/retrace scripts. Validate original occupancy, then freeze a dense longer raster that genuinely exceeds4000 live particles. The brush destroys existing particles inside each stamp before creating/appending its group, so counting input stamps is not particle count. Keep stroke input rate identical before and after; do not raise load until a faster candidate happens to reach it.

Gravity variants: run the same row's script after a fresh `gravity=2` and `gravity=80` construction. For tilt use recorded applied world-gravity vectors at fixed steps, with explicit standard-magnitude and screen orientation metadata; include a browser input-mapping smoke check. Synthetic vectors are reproducible playback, not real phone sensor measurements. Liquid Tumbler's authored9.8 and slider-rebuilt10 are distinct workloads. Applied gravity wakes sleeping bodies; preserve wake semantics.

Initial/drop/drain cases cannot discard their most expensive frames as warmup. When event times are not determined analytically (first spark, bottom-column population, resting basin), instrument the original trajectory for phase discovery, choose fixed step windows, then rerun unchanged source for the actual original measurements. Never independently search before/after for an equally named event and compare unequal trajectories. Preserve phase-discovery logs and recorded population/contact bands.

Add a portrait390×844 profile with its actual DPR and scene portrait bounds for fine-scale/cyclic/high-density cases. Keep viewport, camera, zoom/pan, stroke width, DPR, preferences and actual fallback path frozen between each pair. Desktop and portrait are separate comparisons. Surface modes draw all particles; disc/triangle caps can stride, so explicit full-cap timing prevents downsampling gains. | --- | --- | --- |

| Suite-only averages or single representative scene per family | Can hide unaddressed scenes and regressions. | Individual25 ledgers with workload-specific evidence. |

## Feature dependencies and roadmap implication

`Catalog coverage + deterministic scripts → phase discovery/workload freeze → complete same-source original campaign → scene-specific fresh before → same-workload profile → focused optimization → fidelity + cross-scene canaries → fresh after → independent acknowledgment → next scene → final all25 campaign + summaries`.

The baseline harness is the first dependency. Workload families guide reusable tooling, but do not collapse scene execution into one family result. Process one scene at a time after original coverage is complete; prioritize active-phase cost observed in that campaign and complete the same full cycle for each of the25. A shared optimization may benefit many future scenes, yet each future scene still needs a fresh before, its own profile/hot-path investigation, measured focused work, and a fresh after. If a profile finds no justified improvement, report that candidly and continue investigation; do not fabricate a speedup or silently declare that scene optimized from inherited benefits alone.

Acceptance checks and simplification review belong to each focused change. Preserve current public safe handles, transactional/error semantics, ordering and renderer independence. No extra crates or large profiling dependencies are needed merely to name25 cases: prefer a small validated workload model and thin native/browser adapters around existing production paths.

## Gaps to resolve during harness preparation

- Exact original phase checkpoints and live count/contact envelopes for constructors that fill shapes, carve fixtures, drain, emit or generate sparks; source caps and comments are not observed population results.
- A deterministic browser input barrier that preserves exact step-indexed interaction scripts without substituting a synthetic clock for live-player cadence.
- Targeted extra semantic fields for velocities/groups/body/joints and scene counters; exported frame state alone cannot establish all behavior preservation.
- Available macOS allocation/resident and browser memory metrics, with profiler overhead and unavailable values explicit.
- Exact original control-default behavior and preferences in the rendered player should be checked against source when establishing workloads; never treat the first preset option as the runtime default.
- Real backend/driver and WebGL fallback identity on the local host; use observed identity in the report, not a guessed universal browser configuration.
