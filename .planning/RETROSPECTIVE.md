# Project Retrospective

## Milestone: v1.1 — Web Playground

**Shipped:** 2026-09-20
**Phases:** 6 | **Plans:** 39

### What Was Built

A SolidJS GitHub Pages playground that runs six native Rust/WASM scenes with hash URLs, catalog previews, honest Reset labels, pointer interaction, and automatic main-push delivery.

### What Worked

- Shipping a thin hosted Dam Break slice in Phase 17, then expanding scenes, made Pages delivery real before the catalog was complete.
- Independent AI review bound to exact digests kept phase gates honest without blocking hobby pace.
- A stale milestone audit plus gap-closure phases 20–21 recovered UI fidelity instead of archiving known chrome lies.

### What Was Inefficient

- Post-Phase-18 responsive-shell work undid in-app previews and Reset label honesty, requiring a later audit and two extra phases.
- GSD summary `---` body rules can hide provenance frontmatter from the lifecycle parser.
- Plan one-liners dumped wholesale into MILESTONES.md until curated down to a v1.0-style record.

### Patterns Established

- Product smoke is `just web-player-smoke`; Phase 16 `just web-smoke` stays opt-in forensic chrome.
- Playground WASM stays a private crate; `liquidfun` remains the sole default member.
- Planning archive is not a git release tag.

### Key Lessons

1. Re-audit after gap-closure phases; do not complete a milestone on a stale `tech_debt` audit.
1. Keep empty-hash Dam Break replacement and unknown-hash fallback as distinct useful states.
1. File-length debt on integration-test crate roots needs `foo.rs` plus `foo/` with `#[path]`, not a checker exception.

### Cost Observations

- Model mix: unavailable; no estimates asserted.
- Sessions: multiple discuss/plan/execute/audit turns across 16–21.
- Notable: v1.1 stayed much smaller than v1.0 (39 plans vs 252).

## v1.0 — Experimental Foundation

**Archived:** 2026-09-17. **Phases:** 16. **Active plans:** 252. This milestone was not a package release.

### What was built

Native rigid/particle physics, upstream comparison and replay tooling, private examples/testbed, packaged-consumer isolation, and a practical experimental preparation checklist.

### What worked

- Native consumer isolation, focused regression fixtures and independent review preserved useful confidence.
- Explicitly separating current implementation results from historical strict evidence kept claims honest.
- Archiving superseded plans prevented accidental execution of retired certification work.

### What was inefficient

The original production-quality certification goal accumulated expensive cross-platform campaigns, controlled-host prerequisites and repeated evidence work beyond the owner's hobby needs. Stale generated planning status also required targeted corrections.

### Patterns to retain

Local checks plus one convenient CI job; expensive tools available manually; small source-identified results with honest limitations; preserve failed evidence; review proportional to changed behavior.

### Lessons

1. Revisit the desired quality level before investing in certification infrastructure.
1. Preserve useful tools without turning every possible check into a completion gate.
1. Distinguish implementation completion, experimental package preparation and actual publication.
1. Validate derived planning state after CLI updates rather than assuming generated fields are accurate.

### Cost observations

Session counts, model mix and token/currency totals are unavailable; no estimates are asserted. Future milestones should be much smaller and centered on concrete use.

## Milestone: v1.2 — Native Performance Closing

**Shipped:** 2026-09-21
**Phases:** 4 | **Plans:** 23

### What Was Built

A local Dam Break Medium hunt that persisted an unprofiled Rust-versus-C++ pair, named the hot path from samply, and closed that pair to 2.96× with shared scalar kernels, then recorded playground spot-checks and a WASM smoke note without a public speed claim.

### What Worked

- Exclusive dated stamps, with profiled and timer reports marked `not_timing_authority`, kept the 3× number honest while waves iterated.
- Admitting one named kernel at a time, and keeping failed stamps, made the drop from ~327× to ~21× to ~15× to ≤ 3× reviewable.
- The same-cluster note covered the second canary without inventing a sealed matrix.

### What Was Inefficient

- Early pair ratios near 300× meant several exclusive full 60+600 pairs before the gate, each on one Mac.
- Summary one-liners include an intermediate ≤ 3 stamp (`2026-09-21T20-37-12Z`, ratio `2.953…`) that the honesty docs later replaced with `2026-09-21T20-38-50Z` / `2.956857456935513`. The later stamp is the close number.
- A force-buffer stacking bug showed up in the playground after the gate stamp, so the recorded ratio is not current HEAD.

### Patterns Established

- Unprofiled `just playground-dam-break-bench` is the only 3× authority.
- Shared `liquidfun` kernel edits are the admission path; scene-only or WASM-only shortcuts do not count.
- Planning archive is not a git release tag, and `reviewed_reports` stays empty until a separate public-benchmark decision.

### Key Lessons

1. Rank live profile symbols before editing kernels; the hunt list was not the ranking.
1. Re-pair into a new stamp after each wave, and do not quote samply duration as the gate.
1. A recorded ≤ 3× pair goes stale when a later correctness fix changes the solver. Say which HEAD it measures.

### Cost Observations

- Model mix: unavailable; no estimates asserted.
- Sessions: discuss, plan, execute, and audit across phases 22–25, plus a post-gate dam-break debug.
- Notable: 23 plans in two calendar days, much smaller than v1.0 and smaller than v1.1.

## Milestone: v1.3 — Reference Testbed Scenes

**Shipped:** 2026-09-28
**Phases:** 8 | **Plans:** 38

### What Was Built

Twelve missing JavaScript LiquidFun testbed scenes in the existing playground, then Hydraulic Fountain, Wave Tank, Liquid Bubbler, and Stacked Drip. The six earlier scenes stayed. The catalog now has twenty-three ready scenes.

### What Worked

- Each new scene stayed a native WASM builder in the shared player, with play, pause, and reset already in place.
- Watch-first scenes reused empty controls. Interaction scenes (Soup Stirrer, Impulse, Theo Jansen, Drawing Particles) called live WASM hooks.
- Original hydraulics and fidgets were proven by an original particle id moving, with the revolute motors left off and the neighboring scenes left in place.
- A fresh milestone audit before archive caught that Phases 30–33 had goals but no requirement IDs, and those goals were already verified.

### What Was Inefficient

- Phases 30–33 were added after REQUIREMENTS.md froze at Phase 29, so the traceability table never named the four original scenes.
- The first return shafts for Liquid Bubbler and Stacked Drip drained beside the plate, which took a follow-up plan each.
- Summary one-liners include a Wave Machine line that recorded a RED-stub note instead of the scene result. The curated milestone entry does not repeat it.

### Patterns Established

- A new playground scene needs a catalog record, a portrait frame, a README plan, and a phone-height check.
- Side-shaft returns keep the motor off and move an original particle id. They do not teleport particles.
- Crate publication stays separate from the archive. Annotated tag `v1.3` marks this milestone only.

### Key Lessons

1. Audit before archive, including phases that have no requirement IDs.
1. Keep a new scene beside the one it resembles. Do not reuse that scene's id.
1. A source-text assertion is not the return proof. Keep the behavioral test.

### Cost Observations

- Model mix: unavailable; no estimates asserted.
- Sessions: discuss, plan, execute, and audit across phases 26–33.
- Notable: 38 plans in eight days, larger than v1.2 and close to v1.1.
