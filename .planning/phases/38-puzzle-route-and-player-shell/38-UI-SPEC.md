# Phase 38 — UI Design Contract

> Visual and interaction contract for the `#/puzzle/<id>` route in the existing SolidJS playground. Generated by gsd-ui-researcher for `/gsd-ui-phase` (yolo, non-interactive). The checker upgrades `status` to `approved`.

It reuses the dark tokens in `web/src/app.css`, `web/src/styles/tailwind.css` and `web/src/styles/player-*.css`, the global `button`/`.product-control` primitives in `player-chrome.css`, the `.hud-button` 44 px icon button, the corvu `Drawer` primitives, `ScaleLegend`, `createHudObstacles` and `safeFrame`. | 4 | Etched target line, shadow pass | horizontal segment at `y = minY + (targetCount / fullCount) × height` (first-pour 1.08 m), from `minX` to `maxX`, offset +1 CSS px down | stroke `rgba(7, 16, 24, 0.65)`, `lineWidth 1`, solid |

## HUD Layout

Two layouts apply on canvas stage (the default shell at every size). The panel root sets `data-puzzle-layout="portrait"` when the canvas height is greater than its width, else `"landscape"`. This is the same rule `worldBoundsForTarget` uses, and CSS keys only on this attribute, not on media queries **[UI-D3]**. All leaves mount with the puzzle route, carry `data-hud-obstacle` on the leaf, and have the fixed boxes below in every puzzle phase (`loading`, `building`, `running`, `ended`) and for any text content. Leaf containers use `pointer-events: none`; interactive leaves use `pointer-events: auto`. HUD z-index is 3 (same as `.canvas-hud-corner`).

`inset` below means `max(8px, env(safe-area-inset-<side>, 0px))`. The existing floating site-header trigger occupies the top-left 44×44 at `inset` and is not part of the puzzle HUD.

## Component Contracts

### Level title

- `h2#player-title` (keeps the existing `aria-labelledby="player-title"` pattern), text from the TS title table (D-26), for example "First Pour".
- No chip background; foreground with text shadow. Ellipsis on overflow; `title` attribute carries the full title.

### Fill meter chip (D-11, authoritative readout)

- Chip: `rgb(21 29 40 / 86%)`, `1px solid #2A3441`, radius 8px, padding 8px, `display: grid`, row gap 8px.
- Row 1 (24 px line box): `54%` at 20/600 foreground, then ` / 60%` at 14/400 muted, both tabular.
- Row 2 (16 px zone): bar track 8 px tall, `#0B0F14` with `1px solid #2A3441`, radius 4px, vertically centred; fill `#4DA3FF`, width `fill%` clamped to 0..100, no CSS transition; one 2 × 16 px marker per `GoalTick`, centred on `fraction × track width`, `#E6C35C` for ★ ticks and `#A9B4C0` for others.
- Values: live `floorPercent(goalCount, goalFull)` each presented frame in `running`; `0%` in `building`. In `ended` the meter freezes at the latched value, so it never disagrees with the result card during the settle tail **[UI-D5]**.
- Loading: `--%` and ` / --%`, empty bar, no markers, same box.
- Semantics: `role="meter"`, `aria-label="Cup fill"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` = the shown percent, `aria-valuetext="54% full, target 60%"`. Not focusable, not live.

### Timer chip (D-09)

- Same chip surface. Value centred, 20/600 foreground, tabular, format `m:ss.t` (`0:12.0`).
- `building`: full limit, frozen. `running`: `(stepLimit − stepIndex)` from the presented frame. `ended`: frozen at the outcome step. `loading`: `-:--.-`.
- Semantics: `role="timer"` (implicitly `aria-live="off"`), `aria-label="Simulation time left"`. Do not use `<output>`, whose implicit status role would announce every frame **[UI-D6]**.

### Play transport (D-14 slot; Phase 39 extends it)

- One labeled button: Play icon (22 px) + text "Play", 136×44, `.product-control` metrics, radius 12px.
- `building`: accent (`.product-control--accent` colors), actionable.
- `loading`, `running`, `ended`: `aria-disabled="true"` (not the native `disabled` attribute, so focus can stay on it), styled like `button:disabled` (`#A9B4C0` on `#151D28`, border `#2A3441`, `cursor: default`); the click handler ignores presses.
- Accessible name exactly "Play".

### Result card slot (D-14, D-15)

- Surface: chip surface, radius 12px, padding 8px, `display: grid`, gap 8px, `overflow: hidden`.
- Message element `p.puzzle-result-message`: `aria-live="polite"`, `aria-atomic="true"`.
  - `loading`: "Loading level…" (Body or Label per layout, muted).
  - `building` and `running`: goal text "Fill the cup to 60% before time runs out." (muted; 14/400 in landscape, 16/400 in portrait).
  - `ended`: `<span class="puzzle-result-outcome">Filled!</span> <span class="puzzle-result-score">76% of 60%</span>`, or the same with "Out of time:". The literal space between the spans keeps `textContent` equal to "Filled! 76% of 60%". Outcome word in won/lost color, score in foreground, both 20/600 tabular. In landscape both spans are `display: block` (two lines); in portrait they are inline on one line.
- `ended` adds `box-shadow: inset 3px 0 0 <won or lost color>`; set `data-outcome="won|lost"` on the slot.
- Actions (rendered only in `ended`; the slot box is fixed by CSS, not by content):
  - Landscape: Next, Retry, Edit stacked vertically, each 120×44 (fills the rail inside padding).
  - Portrait and form-factor: one row of three equal-width buttons, each 44 px tall.
  - Order: Next, Retry, Edit.
  - Next with a next level: accent, accessible name "Next level" (visible "Next").
  - Next with no next level (Phase 38, `first-pour` only): native `disabled`, visible "Next", `aria-label="Next: No next level yet"` (keeps the visible word in the name and contains D-15's text), `title="No next level yet"`.
  - Retry: accent when Next is unavailable, otherwise default; visible and accessible name "Retry".
  - Edit: default button; visible and accessible name "Edit".

### Puzzle options drawer (D-24)

- Trigger: `.hud-button` 44×44 with the options icon, `aria-label="Puzzle options"`, wrapped by `DrawerTrigger`, bottom drawer (`side="bottom"`), sheet class `canvas-controls-sheet` (existing look).
- `DrawerLabel` "Puzzle options"; visually hidden `DrawerDescription` "Display options and project details for this puzzle."

- Body (`.fallback-copy`): "No level is called “{raw}”. Open First Pour to start playing, or go back to the scenes." ## Accessibility Contract

- **Touch targets:** every interactive element is at least 44×44 CSS px (Play, Next, Retry, Edit, options trigger, drawer controls, fallback links, Try again).
- **Focus order (DOM order):** site-header trigger (existing) → Play → result actions (Next, Retry, Edit; present in `ended` only) → Puzzle options trigger. The title, meter, timer and legend are not focusable. Visual position may differ by layout, but DOM order is fixed.
- **Focus management [UI-D8]:** when a phase change removes or disables the control that has focus, and focus is inside the puzzle panel, move focus: to Play when entering `building` or `running`, and to the primary result action (Next if enabled, else Retry) when entering `ended`. Never move focus when it is outside the panel, for example in the open drawer.
- **Live regions:** only the result message (`aria-live="polite"`, `aria-atomic="true"`), which announces the goal on load or Edit and the outcome at the latch, and the failure heading (`aria-live="assertive"`). The meter (`role="meter"`) and timer (`role="timer"`) are not live and must not announce per frame.
- **Disabled semantics:** Play uses `aria-disabled` to keep focus; unavailable Next uses native `disabled` (focus never targets it because it is never the primary action while disabled).
- **Numbers:** `tabular-nums` on every changing number so digits do not shift and boxes stay fixed.
- **Contrast:** foreground `#F4F7FA` and muted `#A9B4C0` on `rgb(21 29 40 / 86%)` over `#071018` meet WCAG AA for 14 px and larger text; accent buttons use `#0B0F14` on `#4DA3FF` (existing pairing). Won `#3DDC97`, lost `#F07178` and amber `#E6C35C` are used at 20/600 or as non-text markers.
- **Reduced motion:** puzzle chrome has no motion. With `prefers-reduced-motion: reduce`, building still never auto-plays (it never does), and Play still runs the simulation because the user started it. The settle tail runs normally.
- **Text safety:** the raw unknown id renders through text bindings only and is truncated to 80 characters.
- **Keyboard:** native buttons only; no global shortcuts in this phase.
