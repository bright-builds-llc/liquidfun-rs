Soundness argument. Put it in the module doc of `moving_fixture_query.rs`. For a moving fixture at iteration 0, `S(p) = collision_start_from_previous_transform(p, ...)` is a rigid motion `S(p) = R p + t`, so `S(p) - p = (R - I) p + t` is affine in `p`. `E(p) = p + dt * v` satisfies `|E(p) - p|_inf <= motion`. If the travel box of `[S(p), E(p)]` overlaps the fixture AABB `A`, some point `q` of that box lies in `A`, and on each axis `|q_i - p_i| <= max(|S_i(p) - p_i|, |E_i(p) - p_i|)`. So `p` lies in `A` padded by `r` whenever `r >= max(motion, D(r))`, where `D(r)` is the largest `|S(p) - p|_inf` over `A` padded by `r`. `|S(p) - p|_inf` is convex in `p`, so `D(r)` is attained at one of the 4 corners of that box. Moving a corner outward by `r` changes `(R - I) p` by at most `L * r` in the inf norm, where `L = ||R - I||_inf = |cos d - 1| + |sin d|` and `d` is the net rotation angle of `S`. So `D(r) <= D0 + L * r`, with `D0` the corner maximum over `A` itself. `D(r)` grows with `r`, so iterating `r = need(r)` creeps toward the fixed point without ever verifying; at washing-machine rotation it never converges. The pad therefore comes from the closed form with an overshoot, and is then verified. **Soundness requires `L < 1`**; otherwise there is no finite pad and the full scan is used.

1. New `crates/liquidfun/src/world/particle_coupling/moving_fixture_query.rs`, declared as `mod moving_fixture_query;` in particle_coupling.rs, with:
```rust
/// Smallest verified pad r so every particle whose iteration-0 travel box can
/// overlap `aabb` lies inside `aabb` padded by r; None when it does not converge.
pub(super) fn moving_fixture_query_pad(aabb: Aabb, motion: f32, previous: Transform, current: Transform,
    body_local_center: Vec2, is_circle: bool) -> Option<f32>
```
   Algorithm:
   - `corner_displacement(box) -> Option<f32>`: for each of the 4 corners `c` of `box`, compute `s = collision_start_from_previous_transform(c, previous, current, body_local_center, is_circle, 0).ok()?`, and return the max of `max(|s.x - c.x|, |s.y - c.y|)`.
   - Net rotation of `S`: for `is_circle` the start computation rotates by `R_prev` and then `R_cur^-1` inside `T_cur ∘ T_prev^-1`, so the net rotation is the identity and `L = 0`. Otherwise `cos d = c_cur * c_prev + s_cur * s_prev` and `sin d = s_cur * c_prev - c_cur * s_prev`, from `Transform::rotation()` `.cosine()` / `.sine()`. Then `L = |cos d - 1| + |sin d|`.
   - Margins: `const RELATIVE_MARGIN: f32 = 1.0e-3; const ABSOLUTE_MARGIN: f32 = 1.0e-3;`. They cover f32 rounding in the per-particle start computation, which is far below 1 mm at playground coordinates.
   - Let `l = L * (1.0 + RELATIVE_MARGIN)`. If `!(l < 1.0)`, return `None`.
   - `d0 = corner_displacement(aabb)?`. Closed-form candidate: `r = (motion.max(d0) * (1.0 + RELATIVE_MARGIN) + ABSOLUTE_MARGIN) / (1.0 - l)`, then overshoot: `r = r * 1.05 + ABSOLUTE_MARGIN`.
   - Verify: `need = motion.max(corner_displacement(aabb padded by r)?) * (1.0 + RELATIVE_MARGIN) + ABSOLUTE_MARGIN`. Return `Some(r)` when `r.is_finite() && need <= r`, otherwise `None`. There is no fixed-point iteration. The closed form makes `r` a true upper bound when `L < 1`, and the corner check confirms it with the actual f32 start computation. Washing-machine numbers: `d ≈ 0.0349`, `L ≈ 0.0355`, `D0 ≈ 0.056` at about 1.6 m, so `r ≈ 0.063`.
