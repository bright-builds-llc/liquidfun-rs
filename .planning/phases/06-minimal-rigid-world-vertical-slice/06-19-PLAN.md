# Plan 06-19: Implicit Aggregate Mass Atomicity

<objective>
Close `implicit-aggregate-mass-atomicity` by making type changes and fixture destruction use the same complete prospective-state discipline already proven for fixture creation and explicit reset.

Purpose: Safe public input must never trigger a panic or leave topology and mass state partially changed.
Output: Typed fallible transition APIs, candidate-first implicit resets, cascade-safe removal, and exact no-effect regressions.
</objective>

<threat_model>

## Trust boundaries

| Threat | Boundary | Mitigation |
| --- | --- | --- |
| Partial body transition | A static body's individually valid fixture masses can overflow only when changing to dynamic | Build the new-type BodyState from the complete source-ordered aggregate before destroying contacts, changing type, setting pending flags, or touching proxies. |
| Partial fixture destruction | Density edits can leave a currently committed dynamic body with an aggregate that fails only when a later destruction resets mass | Compute the exact remaining-fixture BodyState before contact, proxy, arena, or adjacency removal; commit topology and the prevalidated state only afterward. |
| Panic denial of service | Recoverable AggregateMassError is routed through expect | Introduce typed public errors and remove every AggregateMassError expect reachable from checked consumer state. |
| Cascade regression | Body destruction removes fixtures through a helper that unnecessarily resets a soon-to-be-destroyed parent | Make body-cascade removal explicitly skip parent mass recomputation while retaining contact/proxy/destruction ordering. |
| Diagnostic ambiguity | A rejection changes hidden adjacency while public counts appear stable | Add private adjacency assertions plus public snapshot/contact/proxy/mass bit checks around both failures. |
</threat_model>
