## Trust boundaries

| Threat | Boundary | Mitigation |
| --- | --- | --- |
| Stale binary spoofing | A child reports a structurally valid canonical D1 identity with old adapter bytes | Independently hash the reviewed adapter-input manifest and current files, then compare before any stage write. |
| Compile provenance spoofing | A child reports canonical compiler fields but a compile digest unrelated to the selected preset's effective database | Normalize and hash exactly the four reviewed result translation-unit commands from the current preset database and require equality. |
| Time-of-review drift | Checkout or build database changes after staging | Recompute both digests during every rigid candidate replay used by review and promotion before their first mutation. |
| Path or diagnostic abuse | Malformed manifests/databases escape the repository or produce unbounded errors | Validate relative unique adapter paths, fixed preset directories, four unique units, shared flags, and bounded typed error text without dumping source or compile databases. |
| False test authority | Fake D1 passes by hardcoding arbitrary but internally consistent digests | Make the fake compute current fixture-repository digests and introduce isolated stale-adapter/stale-compile modes. |
</threat_model>
