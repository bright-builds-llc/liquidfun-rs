# Phase 16 — UI Design Contract

> Visual and interaction contract for the minimal Rust/WASM browser proof. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none |
| Font | system UI stack: `ui-sans-serif, system-ui, sans-serif` |

Phase 16 uses semantic HTML and one page-scoped CSS file. The absence of a component library is locked by `16-CONTEXT.md` D-11 and is a phase-scoped exception to the managed SolidJS library preference. No `components.json`, Tailwind configuration, PostCSS configuration, existing TSX component set, or frontend stylesheet was detected.

The page is a local technical proof, not the public Pages product. Source, maintainer, version, build, gallery, and footer chrome are deferred to the shared public experience in Phases 17 and 18.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-dot and label gaps |
| sm | 8px | Inline metadata and heading stack |
| md | 16px | Default control, metric, and narrow-page spacing |
| lg | 24px | Panel sections and desktop content gaps |
| xl | 32px | Desktop page padding and heading-to-panel gap |
| 2xl | 48px | Optional large-screen top and bottom breathing room |
| 3xl | 64px | Maximum page-level vertical margin on tall screens |

Exceptions: the Dispose button has a 44px minimum block size for keyboard and pointer operability. One-pixel borders and a two-pixel focus outline are visual strokes, not layout spacing.

## Typography

Use exactly four sizes and two weights across the proof.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Section heading / metric | 20px | 600 | 1.3 |
| Page heading | 28px | 600 | 1.2 |

Counts use tabular numerals when supported. Do not introduce a display face, web font, all-caps paragraph text, or weights other than 400 and 600. The page heading is the only `h1`; “Session status” is an `h2`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` | Page background and surrounding negative space |
| Secondary (30%) | `#151D28` | Proof panel, status strip, and canvas frame |
| Accent (10%) | `#39D3C7` | Running indicator, keyboard focus ring, and Rust-provided particle highlights |
| Destructive | `#F87171` | Failure state and Dispose session action only |
| Primary text | `#F4F7FA` | Headings, status, identity, and button text |
| Muted text | `#A9B4C0` | Description, labels, caption, and disposed state |
| Border | `#2A3441` | Panel, metadata groups, and canvas boundary |
| Canvas | `#071018` | Viewport clear color |
| Rigid geometry | `#CBD5E1` | Basin and dynamic rigid-body outline |

Accent reserved for: the running status dot, the Dispose button focus outline, and particle colors supplied by the Rust frame. Accent is not used for headings, panel borders, body copy, or decorative gradients.

The page follows a visual 60/30/10 hierarchy: most pixels remain dominant background, the single proof panel and framed viewport provide the secondary layer, and accent occupies only small state and simulation details. Status meaning must always be present in text; color is supplementary.

The Dispose button uses `#7F1D1D` background, `#FCA5A5` border, and `#FFFFFF` text; hover uses `#991B1B`. Disabled state uses the secondary surface, border color, and muted text. No gradients, glow effects, or translucent glass surfaces.

## Page Structure and Layout

Use this semantic order:

1. `<main aria-labelledby="proof-title">`
1. A `<header>` containing the `h1` and one-sentence summary.
1. A `<section aria-labelledby="session-status-title">` containing the `h2`, status output, runtime identity, counts, viewport figure, and Dispose button.
1. A `<figure>` containing the `<canvas>` and visible `<figcaption>`.
1. A `<dl>` for runtime identity and particle/rigid counts.

Desktop contract:

- Center one content column with `max-width: 960px`.
- Give the page 32px inline padding, 48px top/bottom padding, and a 32px gap between header and proof panel.
- Give the proof panel a one-pixel border, 12px radius, and 24px padding.
- Place status and runtime identity in a wrapping row with 16px gaps. Place counts in a compact two-column definition list beneath it.
- Place the viewport 24px below status metadata and the Dispose button 24px below the viewport caption.
- Keep the button content-width on desktop; do not add adjacent controls.

The layout contains one panel only. Do not add a navbar, route shell, sidebar, card grid, footer, badges, scene selector, playback toolbar, source links, or decorative hero treatment.

## Viewport Contract

- The Canvas viewport is the page's primary visual focal point.
- Use a Canvas 2D viewport with a 16:9 CSS aspect ratio and `width: 100%`.
- Use an intrinsic design size of 960 by 540 CSS pixels. Scale backing-store dimensions by `min(devicePixelRatio, 2)` and redraw after size changes.
- Fit the fixed Rust world bounds inside the viewport with a 16px internal inset. Preserve aspect ratio and center the world; do not stretch physics coordinates.
- Invert the world y-axis only in the pure projection function. Browser code must not interpolate, integrate, or otherwise alter Rust positions.
- Clear to `#071018` for every frame. Draw particles first, then basin segments and the dynamic rigid circle so rigid boundaries remain legible.
- Draw each particle as a filled circle using Rust-provided position, radius, and color. Do not replace particles with DOM/Solid components or add trails.
- Draw basin segments with a 2px `#94A3B8` stroke. Draw the dynamic circle with `#334155` fill and 2px `#CBD5E1` stroke.
- The canvas is not interactive or focusable in this phase. Set no pointer handlers; preserve ordinary page scrolling and default touch behavior.
- Give the canvas `role="img"` and the accessible name `Live Rust physics scene: particles moving in a basin around a rigid body.` Include fallback text inside the element: `Canvas is required to display the Rust/WASM physics proof.`
- Keep status and counts in DOM text outside the canvas. Never rely on drawn text to communicate loading, failure, identity, or disposal.

Loading leaves the viewport cleared to its canvas color. Failure preserves the last successfully drawn frame when one exists; otherwise it remains cleared. Disposal preserves the last frame as diagnostic evidence but stops all subsequent drawing.

## State and Interaction Contract

| State | Visible treatment | Behavior |
|-------|-------------------|----------|
| Loading | `Loading Rust/WASM session…`; identity visible; counts show em dashes; cleared viewport; Dispose disabled | Await generated initializer, construct the Rust session, validate a frame, and draw it before leaving this state |
| Running | `Running Rust/WASM session`; accent dot; numeric counts; live viewport; Dispose enabled | Request one bounded Rust step per animation frame, capture one owned frame, draw it, and free the frame wrapper |
| Failure | `Rust/WASM session failed`; fixed error copy in destructive color; identity visible; last counts/frame retained when available; Dispose disabled | Cancel animation, dispose the owner exactly once when possible, and perform no automatic retry |
| Disposed | `Rust/WASM session disposed`; muted status; last counts/frame retained; Dispose disabled | Cancel animation before freeing the session; perform no more steps, frame captures, or draws |

“Running” is permitted only after WASM initialization, session construction, frame validation, and the first successful canvas draw. A compile-only or canned-motion state must never produce the running copy.

The status text is an atomic polite live region. The fixed error sentence uses `role="alert"` only while failure is present. Avoid announcing changing counts every frame; the count definition list is not a live region.

### Dispose session

- Use a native `<button type="button">` with the exact label `Dispose session`.
- Enable it only in Running. Loading, Failure, and Disposed use the native `disabled` attribute.
- Activation cancels the pending animation frame, disposes the TypeScript owner exactly once, then moves to Disposed.
- Enter and Space use native button activation. Do not add custom keyboard handlers for those keys.
- Show a 2px solid `#39D3C7` `:focus-visible` outline with a 4px outline offset. Never remove the browser focus indicator without this replacement.
- Hover may darken the button only when enabled. Disabled treatment must not look clickable.
- Do not show a confirmation dialog: the operation releases transient local resources and is the proof itself.
- Do not add retry, recreate, play, pause, reset, or scene-control behavior.

## Narrow-Viewport Minimum

This phase requires containment, not final responsive polish.

- At viewport widths of 480px or less, use 16px page and panel padding and 16px vertical gaps.
- Keep the page and panel at `min-width: 0`; no element may cause horizontal page scrolling at 320px viewport width.
- Stack status metadata and definition-list entries into one column.
- Keep the canvas at full available width and 16:9. At a 320px viewport, the expected content canvas is at least 256px wide after page and panel padding; it may become visually compact but must remain fully visible.
- Make the Dispose button full-width while retaining its 44px minimum block size.
- Allow heading and fixed status/error copy to wrap naturally. Do not truncate, marquee, horizontally scroll, or reduce type below the declared scale.
- Do not add mobile navigation, orientation handling, touch simulation controls, or breakpoint-specific scene behavior.

---

## Motion and Accessibility Minimum

- Add no cosmetic animation, pulsing, shimmer, or transition. The physics scene is the only continuous motion.
- Do not flash the viewport or status. State changes are immediate and text-backed.
- `prefers-reduced-motion` does not stop the required proof simulation in Phase 16; the independent text status and counts make the running state observable without interpreting motion. User-controlled playback belongs to Phase 17.
- Maintain at least WCAG AA text contrast for declared text/surface pairs.
- Preserve document zoom, text wrapping, and browser defaults. No keyboard trap or focus movement is introduced.

---

## Explicit Phase Boundaries

Do not add:

- routing, stable scene URLs, or Pages base-path behavior;
- gallery cards, previews, or any of the six-demo catalog;
- play, pause, reset, retry, scene selection, or scene controls;
- source, maintainer, version, build, inspiration, attribution, or footer chrome;
- pointer/touch physics interaction or canvas keyboard controls;
- final responsive layouts, reduced-motion playback controls, or broad accessibility polish;
- an external renderer, JavaScript physics engine, or per-particle Solid state.

These are deliberate later-phase boundaries from `16-CONTEXT.md` D-15 and the roadmap, not omissions to fill during Phase 16 implementation.
