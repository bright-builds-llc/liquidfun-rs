### Valve opening-time readout (D-04)

**[UI-D55] Describe the stepper group by the readout; no live region.**

- `span.puzzle-valve-time`: remove `aria-hidden="true"`. Add `id="puzzle-valve-time"`. A fixed id is safe because the selection bar mounts once per puzzle route, the same pattern as `#puzzle-editor-status`. Keep `class`, `data-enabled`, the text (`valveStepperModel().text`) and every style.
- `div.puzzle-valve-stepper[role="group"][aria-label="Valve opening time"]`: add `aria-describedby="puzzle-valve-time"` **only while** `valve().enabled` is true. When the model is disabled (no valve selected, or not building), omit the attribute (`undefined` in Solid). This way the group is not described by the "–" placeholder. **[UI-D56]**
- Do not add `aria-live`, `role="status"` or `aria-atomic` to the readout or the group. Committed changes are already announced once by `#puzzle-editor-status` through `editor-announce.ts` ("Valve opens at 2.5 s"). A second live region would announce them twice.
- Expected screen-reader result when focus moves into the stepper with a valve selected: group "Valve opening time", description "2.5 s", then the focused button "Open the valve 0.5 s earlier". No other ARIA in the selection bar changes.
- e2e and unit hooks: `.puzzle-valve-time` has no `aria-hidden` attribute and has `id="puzzle-valve-time"`. With a valve selected, `.puzzle-valve-stepper` has `aria-describedby="puzzle-valve-time"`, and Playwright `toHaveAccessibleDescription("2.5 s")` (or the current text) passes on the group. With no valve selected, the attribute is absent. Existing `puzzle-valve.spec.ts` locators (`.puzzle-valve-time` text) keep working.

### Valve tick cap (D-05)

No visual change. Because `maxOpenTick` now caps at 255, the "later" stepper button becomes `aria-disabled` at 127.5 s on any level whose step limit exceeds 7,650 steps. No shipped level reaches that limit, so no level's visible behavior changes.
