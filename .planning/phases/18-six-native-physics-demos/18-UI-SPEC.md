# Phase 18 — UI Design Contract

> Visual and interaction contract for the six-card catalog, per-scene bounded controls, and player credit chrome. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Reuse the approved Phase 17 dark playground tokens, type scale, spacing, player states, footer, and semantic-HTML exception. This phase evolves the honest name list into six ready cards and adds scene controls plus per-scene credits. It does not adopt a component library.

| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4). Reuse the Phase 17 CSS custom properties:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-dot gaps, definition-term spacing, current-card accent marker, preview stroke inset |
| sm | 8px | Inline metadata, heading stacks, toolbar and card-action padding, footer row gaps, control-group internal gaps |
| md | 16px | Default control, card-grid, credit-row, and narrow-page spacing |
| lg | 24px | Player-panel sections, catalog-to-player gap, desktop content gaps, card internal padding |
| xl | 32px | Desktop page padding and header-to-catalog gap |
| 2xl | 48px | Desktop top and bottom page padding |
| 3xl | 64px | Maximum page-level vertical margin on tall screens |

Exceptions: Play, Pause, Reset, Retry, Open, Apply, and every scene action button have a 44px minimum block size. Native `<select>` controls also use a 44px minimum block size. One-pixel borders and a two-pixel focus outline are visual strokes, not layout spacing. Do not introduce 44px as a spacing-scale token.

Source: `17-UI-SPEC.md` Spacing Scale. Confirmed by `18-CONTEXT.md` reuse of the 8-point scale.

## Typography

Use exactly four sizes and two weights across the public site.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / caption / footer / credit / reset-hint | 14px | 600 labels and credit terms; 400 captions, footer body, reset-hint, card preview caption | 1.4 |
| Body / card title / card description / control value | 16px | 400 descriptions and body; 600 card titles, control labels, and buttons | 1.5 |
| Section heading / scene title | 20px | 600 | 1.3 |
| Page heading | 28px | 600 | 1.2 |

Do not introduce a display face, web font, all-caps paragraph text, or weights other than 400 and 600. The site heading is the only `h1`. The player or fallback heading is the only `h2` on a given view. Catalog label `Scenes` remains a styled paragraph (`.catalog-heading`), not an `h2`. Card titles are styled paragraphs or `<strong>`, not headings. Provenance values may use tabular numerals. Allow wrapping; never truncate, marquee, or shrink below this scale.

Source: `17-UI-SPEC.md` Typography, `18-CONTEXT.md` D-15.

## Page Structure and Layout

Use this semantic order on every view:

1. `<main aria-labelledby="site-title">`
1. A `<header>` containing the `h1` and one-sentence summary.
1. A `<nav aria-labelledby="scene-nav-title">` containing the `Scenes` label and a six-card list in this exact order: Dam Break, Fountain, Float or Sink, Color Mixer, Jelly Drop, Water Wheel.
1. A `<section aria-labelledby="player-title">` for the shared player or fallback. This is the only runtime surface.
1. A `<footer>` containing source, FOSS, maintainer, and provenance chrome.

Desktop contract (≥721px viewport width):

- Center one content column with `max-width: 960px`.
- Give the page 32px inline padding, 48px top and bottom padding, and 32px between header and catalog.
- Place a 24px gap between catalog and player, and 32px between player and footer.
- Catalog is a three-column CSS grid with 16px row and column gaps. Do not use a wrapping name-and-chip list.
- Each card is a `<li>` containing, in order: static preview frame, `Static preview` caption, scene title, one-sentence description, and one `Open` hash link.
- Give catalog, each card, player, and footer a one-pixel `#2A3441` border, 12px radius, and 24px padding on the secondary surface. Card padding may be 16px when needed to keep three columns inside 960px; do not go below 16px.
- Preview frame is 16:9, `width: 100%`, background `#071018`, 1px border, 12px radius. SVG is inline, not an `<img>` network asset, and not a `<canvas>`.
- Place scene title, status, and runtime identity in a wrapping row with 16px gaps.
- Place the viewport 24px below that row, the playback toolbar 24px below the caption, scene controls 24px below playback, and credits 24px below scene controls.
- Place Play, Pause, and Reset in one wrapping row with 8px gaps. Show Retry only in failure, first in that row.
- Keep playback buttons content-width on desktop; do not stretch them into a full-width bar.
- Scene controls wrap in a row or two-column grid with 16px gaps. Each labeled group stays content-width on desktop.
- Credits are a compact definition list inside the player panel, not a second footer.

Mid-width contract (481px–720px): catalog is a two-column grid with 16px gaps. Player and footer rules stay the same as desktop except padding follows the narrow rule at 480px and below.

Do not add a marketing hero, sidebar, search, filters, scene editor, live WASM thumbnails, or a second page heading.

Source: `18-CONTEXT.md` D-01, D-02, D-12; `17-UI-SPEC.md` page chrome; `18-RESEARCH.md` Pattern 5.

## Viewport Contract

- The Canvas viewport is the primary focal point only after a ready scene has a drawn frame. Fallback views use the fallback heading and body as the focal point and must not show a blank canvas.
- Use a Canvas 2D viewport with a 16:9 CSS aspect ratio and `width: 100%`.
- Use an intrinsic design size of 960 by 540 CSS pixels. Scale backing-store dimensions by `min(devicePixelRatio, 2)` and redraw after size changes.
- Fit the shared Rust world bounds `(-6,-1)..(6,8)` inside the viewport with a 16px internal inset unless a recorded spike proves a scene cannot fit. Preserve aspect ratio and center the world; do not stretch physics coordinates.
- Invert the world y-axis only in the pure projection function. Browser code must not interpolate, integrate, or otherwise alter Rust positions, colors, or wheel angles.
- Clear to `#071018` for every frame. Draw particles first, then rigid segments, then rigid circles so boundaries remain legible.
- Draw each particle as a filled circle using Rust-provided position, radius, and color. Do not replace particles with DOM/Solid components, add trails, or blend Color Mixer hues in JavaScript.
- Draw rigid segments with a 2px `#94A3B8` stroke. Draw rigid circles with `#334155` fill and 2px `#CBD5E1` stroke. Water Wheel paddles are transformed segment lanes from Rust, not CSS-rotated DOM.
- The canvas is not interactive or focusable in this phase. Set no pointer handlers; preserve ordinary page scrolling and default touch behavior. Pointer aiming, stirring, poking, and stuck-pointer polish belong to Phase 19.
- Give the canvas `role="img"` and the accessible name `Live {Scene name} scene: Rust particles and rigid bodies.` Include fallback text inside the element: `Canvas is required to display the {Scene name} scene.`
- Keep status, controls, and credits in DOM text outside the canvas. Never rely on drawn text to communicate loading, pause, failure, reset, or credits.

Loading leaves the viewport cleared to its canvas color with the loading empty-state overlay. Playing and paused show the last drawn Rust frame. Failure preserves the last successfully drawn frame when one exists; otherwise it remains cleared with the error copy outside the canvas. Fallback views omit a live session and show the fallback copy instead of a cleared mystery canvas.

Source: `17-UI-SPEC.md` Viewport Contract, `18-CONTEXT.md` D-06, D-09, `18-RESEARCH.md` Pattern 4.

## State and Interaction Contract

| State | Visible treatment | Behavior |
|-------|-------------------|----------|
| Loading | `Loading {Scene name}…`; muted status; identity visible; loading overlay; Play/Pause/Reset and scene controls disabled; Retry hidden | Await generated initializer, construct the selected scene, validate a frame, and draw it before leaving this state |
| Playing | `Playing`; accent status dot; live viewport; Pause, Reset, and scene controls enabled; Play disabled; Retry hidden | Advance the current session with Phase 17 ownership, hidden-tab, and catch-up caps |
| Paused | `Paused`; muted status; last frame retained; Play, Reset, and scene controls enabled; Pause disabled; Retry hidden | Freeze the world without disposing it. Do not step. Redraw on resize only. Runtime control changes that do not recreate may still apply, then wait for Play to show motion |
| Failure | `{Scene name} failed`; destructive status and error copy; last frame retained when available; Retry and Reset enabled; Play/Pause and scene controls disabled | Stop the session. Retry or Reset recreates the current scene from its documented initial state plus the last applied construction presets |
| Fallback | Fallback heading and body; no live session; `Open Dam Break` enabled; Play/Pause/Reset/Retry and scene controls hidden | Do not construct a WASM world |

Playing is permitted only after WASM initialization, selected-scene construction, frame validation, and the first successful canvas draw. A compile-only or canned-motion state must never produce the playing copy.

Default after a successful load: start Playing so a visitor sees real Rust motion. If `prefers-reduced-motion: reduce` is active, draw the first frame and enter Paused instead.

Hidden-tab suspension is not a distinct visual state. If the document is hidden while Playing, pause stepping without changing the Playing label; on resume, clear catch-up time and continue Playing. User-visible `Paused` is only for an explicit Pause scene action or the reduced-motion start.

The status text is an atomic polite live region. The fixed error sentence uses `role="alert"` only while failure is present. Do not announce frame counts or step indexes.

### Playback controls

- Use native `<button type="button">` elements with the exact labels `Play scene`, `Pause scene`, `Reset scene`, and `Retry scene`.
- Enter and Space use native button activation. Do not add custom keyboard handlers for those keys.
- Show a 2px solid `#39D3C7` `:focus-visible` outline with a 4px outline offset on buttons, selects, and in-page links. Never remove the browser focus indicator without this replacement.
- Hover may change fill only when enabled. Disabled treatment must not look clickable.
- Play starts or resumes stepping. Pause freezes the world without disposing it. Reset disposes the current session and recreates the current scene from its documented initial state. Retry does the same recreate after failure.
- Do not show a confirmation dialog. Reset, Retry, and Apply release only transient local resources.
- Do not restore `Dispose session`.

### Scene controls

- Render each scene's two or three locked controls from catalog metadata. Do not invent a fourth control in the player chrome.
- Recreating presets: `<label>` + native `<select>` + `Apply` button, with the construction reset hint visible before Apply. Changing the select does nothing until Apply.
- Runtime presets: `<label>` + native `<select>`; apply on `change` without a reset hint.
- Actions: native `<button type="button">` with the locked verb+noun label.
- After a recreating Apply, the player may pass through Loading and then return to Playing (or Paused when reduced motion is active).
- Obstacle drop/reset, Drop body, and Poke jelly do not recreate the world and do not show the reset hint.

### Catalog interaction

- Every shipped card `Open` link is keyboard-operable as a hash link.
- Visiting a shipped scene hash starts that scene. Visiting empty or unknown hashes must not start physics, show a spinner that implies a load, or silently redirect without the matching fallback copy.

Source: `18-CONTEXT.md` D-04, D-05, D-06; `17-UI-SPEC.md` State and Interaction Contract.

## Narrow-Viewport Minimum

This phase requires readable containment, not Phase 19 accessibility acceptance.

- At viewport widths of 480px or less, use 16px page, card, and panel padding and 16px vertical gaps.
- Keep the page and panels at `min-width: 0`; no element may cause horizontal page scrolling at 320px viewport width.
- Catalog becomes one column. Cards, status metadata, scene controls, credits, and footer rows stack into one column.
- Keep the canvas at full available width and 16:9 on a ready scene. At a 320px viewport, the expected content canvas is at least 256px wide after page and panel padding.
- Make Play, Pause, Reset, Retry, Open, Apply, scene actions, fallback Open Dam Break, and selects full-width while retaining the 44px minimum block size.
- Allow heading, card titles, descriptions, status, fallback, error, credits, and footer copy to wrap naturally.
- Do not add a hamburger, orientation handling, canvas pointer capture, or breakpoint-specific physics.

## Motion and Accessibility Minimum

- Add no cosmetic animation, pulsing, shimmer, or transition. The physics scene is the only continuous motion. Catalog SVGs stay still.
- Do not flash the viewport or status. State changes are immediate and text-backed.
- `prefers-reduced-motion: reduce` starts the selected scene paused after the first drawn frame. The visitor can press Play scene.
- Maintain at least WCAG AA text contrast for declared text/surface pairs, including inverse text on accent-filled buttons.
- Preserve document zoom, text wrapping, and browser defaults. No keyboard trap. Hash navigation must not steal focus away from the player heading except when the user activates a catalog or fallback link.
- Construction reset is announced by visible hint text, not color alone.
- Pointer, stuck-pointer, narrow-width keyboard/focus acceptance, and concise on-canvas interaction instructions remain Phase 19. This phase still requires readable cards, labeled controls, visible focus, and text status.

Source: `17-UI-SPEC.md` Motion and Accessibility Minimum, `18-CONTEXT.md` D-16.

## Explicit Phase Boundaries

Do not add:

- live WASM catalog thumbnails, animated fake-physics previews, or extra catalog search/filters;
- MysticUI, Tailwind, shadcn, or an icon package;
- pointer/touch aiming, stirring, poking, stuck-pointer handling, or canvas keyboard controls as Phase 18 acceptance;
- final narrow-width accessibility acceptance or the six-scene WEBTEST-01 browser matrix;
- seed/control values in share links, a scene editor, or diagnostic-catalog playback;
- fake buoyancy, JavaScript color blending advertised as mixing, or scripted wheel rotation;
- silent scene substitution or “not ready” chips on shipped approved ids;
- WASM workers, threads, zero-copy views, WebGPU, SSR, or accounts;
- Linux native qualification, oracle, sanitizer, coverage, or performance gates;
- changes to the Phase 17 Pages workflow or `/liquidfun-rs/` production base unless a scene asset path requires it.

These are locked later-phase or out-of-scope boundaries from `18-CONTEXT.md`, not omissions to fill during Phase 18 implementation.
