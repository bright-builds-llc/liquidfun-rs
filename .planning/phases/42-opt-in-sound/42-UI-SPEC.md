Generated by gsd-ui-researcher for `/gsd-ui-phase` (yolo, non-interactive). The checker upgrades `status` to `approved`.

This contract **extends** the approved Phase 38, 39 and 41 contracts (`38-UI-SPEC.md`, `39-UI-SPEC.md`, `41-UI-SPEC.md`). Every token, typography role, color, chip surface, focus rule, live-region rule, HUD leaf and box size from those contracts stays in force unless a row below names it as changed. ## Component Contracts

### HUD sound button (`PuzzleSoundToggle`, D-01, D-05, D-11)

Markup, canvas stage only:

```
<div class="puzzle-options-slot" data-hud-obstacle>      (existing leaf, now 96×44)
  <button class="hud-button puzzle-sound-toggle" type="button" ...>   NEW, first child
  <DrawerTrigger class="hud-button canvas-controls-trigger puzzle-options-trigger">  existing, second child
</div>
```

- The sound button comes **first** in the slot, so it sits on the left and the options trigger keeps the top-right corner it has on every other route. DOM order is focus order: ... result actions → Sound → Puzzle options **[UI-D33]**.
- `PuzzleHud` gains a `soundToggle: JSX.Element` prop rendered before `optionsTrigger` inside the slot. Update the `PuzzleHud` doc comment's focus-order sentence.
- The existing `.puzzle-hud .puzzle-options-slot button { pointer-events: auto; }` already covers the new button. Add `gap: 8px` to the slot rule (it is already `display: flex`).

Attributes per state:

| State | `aria-pressed` | `disabled` | `aria-label` | `title` | `aria-describedby` | `data-sound-state` | Icon |
|-------|----------------|------------|--------------|---------|--------------------|--------------------|------|
| Off | `"false"` | no | "Sound" | hint copy | `puzzle-sound-help` | `off` | `SoundOffIcon` |
| On (context running) | `"true"` | no | "Sound" | hint copy | `puzzle-sound-help` | `on` | `SoundOnIcon` |
| On, waiting for first gesture (stored "on", D-04) | `"true"` | no | "Sound" | hint copy | `puzzle-sound-help` | `on` | `SoundOnIcon` |
| Unavailable (no constructor, or construction threw, D-05) | `"false"` | yes | "Sound unavailable in this browser" | "Sound unavailable in this browser" | none | `unavailable` | `SoundUnavailableIcon` |

- The accessible name never changes between on and off; the state is carried by `aria-pressed` (D-01). Screen readers announce the pressed change natively, so no live region is added.
- `puzzle-sound-help` is a `<p id="puzzle-sound-help" class="visually-hidden">` holding the hint copy, rendered in `PuzzlePanel` beside the existing `puzzle-keyboard-help` paragraph, outside the HUD, so it never affects any obstacle box and exists while the drawer is closed **[UI-D34]**.
- Availability is decided at render from `typeof (window.AudioContext ?? window.webkitAudioContext) === "function"`, with no construction (Research Pattern 4). A later construction failure switches the button to the unavailable row for the rest of the page session.
- A runtime audio failure after a context exists (D-08, D-16) switches the button to the **off** row, still enabled, so the player can try again. The stored preference is not overwritten.
- The waiting state has no visual difference from on. The first trusted `pointerdown` (mouse), `pointerup` or `keydown` on the puzzle route creates and resumes the context (D-17).
- **Gesture exclusion [UI-D35]:** the first-gesture unlock listener ignores events whose target is inside `.puzzle-sound-toggle` or the "Sound effects" checkbox. Tapping the toggle while waiting just turns sound off, with no context created. The toggle's own click handler is the only path that creates a context from the toggle.

### Drawer "Sound" section (`PuzzleSoundSection`, D-02, D-11, D-18)

Placement in `PuzzleOptionsSheet` body (canvas stage), top to bottom: `PuzzleLevelLinks` → Particles select → **Sound section** → `GitHubSourceLink` → `SiteFooter`. `PuzzlePanel` passes it as the second child, after `PuzzleRenderModeSelect`. The unknown-level fallback sheet does not get it (no puzzle is loaded there).

Markup:

```
section.puzzle-sound-section  aria-labelledby="puzzle-sound-heading"  data-sound-state="on|off|unavailable"
  h3#puzzle-sound-heading                          "Sound"
  label.player-check
    input[type=checkbox]  aria-describedby="puzzle-sound-hint"   checked = shared sound state
    "Sound effects"
  p#puzzle-sound-note.puzzle-sound-note            (only after a runtime audio failure this session)
  p#puzzle-sound-hint.puzzle-sound-hint            hint copy, or the unavailable line
```

- Style: `.puzzle-sound-section { display: grid; gap: 8px; min-width: 0; }`. No panel surface, no border; it sits flat in the sheet like its neighbours. `h3 { margin: 0; font-size: 16px; font-weight: 600; line-height: 1.4; }`. `.puzzle-sound-hint, .puzzle-sound-note { margin: 0; color: #A9B4C0; font-size: 14px; font-weight: 400; line-height: 1.4; overflow-wrap: anywhere; }`.
- The checkbox and the HUD button read and write one shared state (`controller.soundEnabled()` / `setSoundEnabled`). Toggling one updates the other in the same frame. Turning the checkbox on runs the same create-or-resume path inside its `change` handler, which is a user activation.
- Unavailable: the checkbox is `disabled` and unchecked, the label text stays "Sound effects", and the hint paragraph shows the unavailable line instead of the silent-switch hint (the switch is irrelevant when nothing can play).
- Failure note (`puzzle-sound-note`): shown only after a runtime audio failure turned sound off this session, and removed as soon as the player turns sound on again **[UI-D36]**. Plain text, no icon, no live region: the off state already changed and the note explains it when the player looks.

### Form-factor shell (`?shell=form-factor`, D-18)

- There is no canvas HUD and no drawer, so the HUD button is not rendered. The same `PuzzleSoundSection` renders as the **last item of the second `.control-row`** (after "All levels" and the Particles select) **[UI-D37]**.
- In that row the section takes its own line: `.control-row > .puzzle-sound-section { flex: 1 1 100%; }`.
- The hint is visible text there, so `puzzle-sound-help` is not needed by any control in this shell (it may still render; it is visually hidden and unreferenced).
- No `data-hud-obstacle` anywhere in the form-factor shell (unchanged rule).

### Distinct accessible names (D-18)

| Control | Role | Accessible name | Shell |
|---------|------|-----------------|-------|
| HUD sound button | button (toggle, `aria-pressed`) | "Sound" (unavailable: "Sound unavailable in this browser") | canvas stage |
| Mirror control | checkbox | "Sound effects" | drawer (canvas stage), options row (form-factor) |
| Section heading | heading level 3 | "Sound" | both |

`getByRole("button", { name: "Sound", exact: true })` finds exactly one element on a canvas-stage puzzle route, and `getByRole("checkbox", { name: "Sound effects" })` exactly one while the drawer is open or in form-factor. No other control on puzzle routes is named "Sound" **[UI-D38]**.

### Where sound controls do not appear

Scene routes, the `#/puzzles` grid, the unknown-level fallback and the scene options sheet get no sound control (D-01). The 25 scene HUDs and `CanvasStage.tsx` stay unchanged.

## Interaction and State Contract

| Situation | HUD button | Checkbox | Context | Audible |
|-----------|------------|----------|---------|---------|
| First visit (no stored value) | off | unchecked | none | no |
| Player turns sound on (button or checkbox) | on | checked | created (or resumed) in that handler; stored "on" | voices start at the next run frame; building stays silent |
| Reload with stored "on", before any gesture | on | checked | none | no |
| First trusted gesture on the route (not on a sound control) | on | checked | created and resumed | yes, during a run |
| Player turns sound off | off | unchecked | voices stopped, then suspended; stored "off" | no |
| Tab hidden | unchanged | unchanged | voices stopped, then suspended | no |
| Tab visible again, sound on, still on a puzzle route | unchanged | unchanged | resumed | yes, during a run |
| Leave the puzzle (grid, sidebar, next level route change) | unmounts | unmounts | voices stopped, suspended, kept for reuse | no |
| Stop, Edit, Retry, level change | unchanged | unchanged | all voices stopped immediately | new run only |
| Storage blocked or `setItem` throws | toggles normally | toggles normally | as above | as above; the choice lasts for the page session (D-03) |
| Construction unavailable or threw | unavailable (disabled) | disabled, unchecked | none | no |
| Runtime audio failure | off (enabled) | unchecked, failure note shown | voices stopped; sound off in memory only (D-16) | no |

Rules:

- Toggling never moves focus. The button keeps focus after Enter or Space; the checkbox keeps focus after Space.
- Enter and Space on the focused button toggle it natively. The puzzle keyboard shortcuts (`puzzle-keyboard-help`) are scoped to the build area and do not intercept keys on the sound button.
- No confirmation sound plays when sound turns on. UI ticks are deferred (CONTEXT Deferred Ideas), so the first sounds the player hears come from the next run.
- The drawer may be open while the HUD button changes (for example after a runtime failure); both controls render from the same signal, so they never disagree.
- Toggling changes no box size: the slot, button and icon boxes are fixed, the pressed ring is an inset `box-shadow`, and the section's line count only changes inside the drawer or form-factor row, never on the HUD. The obstacle set and safe frame stay identical between on, off and unavailable. Check this in e2e by reading `HudGeometry` before and after a toggle and comparing the slot box.

## Accessibility Contract

- **Focus order (canvas stage):** "Demos" trigger → caption Dismiss → tray → selection bar → run controls → result actions → **Sound** → Puzzle options. In the open drawer: "All levels" → Particles → **Sound effects** → source link → footer links. Form-factor: first control row → "All levels" → Particles → **Sound effects**.
- **Focus ring:** the global `button:focus-visible` / `input` focus outline (`2px solid #4DA3FF`, offset 4px). On the HUD the 4 px offset fits inside the 8 px slot gap and the 8 px inset, so the ring is not clipped by the viewport edge.
- **Names and states:** see Distinct accessible names. The button exposes `aria-pressed`; the checkbox exposes `checked`; the unavailable button exposes `disabled`. The hint is the button's description (`aria-describedby="puzzle-sound-help"`) and the checkbox's description (`aria-describedby="puzzle-sound-hint"`).
- **Disabled button:** a disabled button is not focusable. The unavailable reason is therefore also visible as text in the drawer and form-factor section, where the disabled checkbox's label and the unavailable line stay readable.
- **Live regions:** none added. Pressed and checked changes are announced natively; the failure note is static text.
- **Non-color cues:** each state has its own icon shape (waves, cross, slash) and the on state adds a 2 px inset ring.
- **Reduced motion:** nothing animates. The toggle and section have no CSS transitions or animations. `prefers-reduced-motion` does not affect audio; sound stays opt-in and off by default.
- **Text safety:** every rendered string is a TS constant; no `innerHTML`.
