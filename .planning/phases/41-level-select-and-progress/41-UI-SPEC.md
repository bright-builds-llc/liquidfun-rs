## Page Layout: `#/puzzles`

**Visual priority:** the "Up next" card (accent border) is the focal point; the page heading is second; the other cards third. On fresh storage, Level 1 is the "Up next" card.

### Structure (DOM order)

```
section.puzzle-select[.puzzle-select--canvas-stage]  aria-labelledby="puzzle-select-title"
  div.puzzle-select-content                          (max-width 960, margin-inline auto, grid, gap 24)
    header.puzzle-select-header                      (grid, gap 8)
      h2#puzzle-select-title          "Puzzles"
      p.puzzle-select-intro           intro copy
      p.puzzle-select-progress        "{N} of 6 solved"
      p#puzzle-progress-note.puzzle-progress-note    (degraded only)
    ol.puzzle-level-grid  aria-label="Levels"        (6 × li, registry order)
  SiteFooter                                         (canvas stage only, 48 px below the grid)
```

### Canvas stage (default shell at every size)

`html[data-canvas-stage]` clips `html`, `body`, `#root`, `.app-shell`, `.app-body` and `.playground-main`, so the page is its own scroll container (Research Pitfall 1, Pattern 10):

- `.puzzle-select--canvas-stage`: `position: fixed; top: var(--visual-viewport-offset-top, 0px); left: 0; width: 100%; height: var(--visual-viewport-height, 100dvh); overflow-x: hidden; overflow-y: auto; overscroll-behavior: contain; background: #0B0F14`.
- Padding: top `calc(max(8px, env(safe-area-inset-top, 0px)) + 60px)`, right `max(16px, env(safe-area-inset-right, 0px))`, bottom `max(16px, env(safe-area-inset-bottom, 0px))`, left `max(16px, env(safe-area-inset-left, 0px))`.
- Content is top-aligned (`align-content: start`), not centred.
- `SiteFooter` renders inline at the end of the scroll container, `margin-top: 48px` from the grid, with the same reset as `.canvas-controls-sheet .site-footer` (no panel surface). The footer holds the GitHub source link, which keeps the `must` source-link rule satisfied on this page (`PlaygroundShell` hides the shell footer in canvas stage).
- No element on this page carries `data-hud-obstacle` (D-02).

### Form-factor shell (`?shell=form-factor`)

- Normal flow inside `.app-body`; the page scrolls with the document and the shell `SiteFooter` shows. The page renders no inline footer.
- The section has no panel surface (transparent, no border, padding 0), so the `#151D28` cards sit on the `#0B0F14` page.
- The same grid rules apply. The content width is the `.app-body` width, so the column count follows the same 576/872 px thresholds.

### Grid

- `ol.puzzle-level-grid`: `display: grid; grid-template-columns: repeat(auto-fill, minmax(min(100%, 280px), 1fr)); gap: 16px; margin: 0; padding: 0; list-style: none`.
- Each `li` stretches to the row height, and each card fills its `li` (`height: 100%`), so cards in one row share a height.
- No CSS transitions or animations.

- Grid → level: card link → `#/puzzle/<id>`; the existing hash lifecycle mounts `PuzzlePanel`.

- Live update (D-11): stars are recorded before the result card renders, so the grid shows the new stars, unlocks and "Up next" on arrival without a reload. A later worse run never lowers a shown star.
- Entering the grid starts the scroll container at the top. There is no scroll restoration and no programmatic focus on entry **[UI-D27]**. Closing the mobile sidebar drawer returns focus to its trigger (existing behavior).

## Accessibility Contract

- **Landmarks and headings:** the site `h1` stays first; the page `h2` "Puzzles"; one `h3` per card. The grid is an ordered list labelled "Levels", in registry order.
- **Card names:** an unlocked card's link name comes from its content ("Level 1 First Pour Water runs downhill… Win: earned Brim: not yet Thrifty: not yet Best fill 90%"). The star slots contribute their `aria-label` because `role="img"` makes their children presentational. A locked card is a `role="group"` named "Level {n}, {Title}, locked"; it is not in the tab order.
- **Focus order:** "Demos" trigger (canvas stage) → unlocked card links in registry order → footer links. Locked cards are skipped.
- **Targets:** every link is at least 44 px tall. Cards are much larger.
- **Current page:** the sidebar Puzzles link uses `aria-current` (UI-D24) as well as its color and inset bar.
- **Non-color cues:** earned and not-yet stars differ by fill as well as color and carry text labels; locked cards add the lock icon, the "Locked" text and the reason line on top of the dashed border; "Up next" is a text tag as well as an accent border.
- **Live regions:** none added. The storage note is static text. The Phase 38/39 result-card and editor regions are unchanged.
- **Reduced motion:** nothing animates.
- **Text safety:** every rendered string comes from TS constants or numbers; the unknown-level raw id keeps its text binding and 80-character truncation.
