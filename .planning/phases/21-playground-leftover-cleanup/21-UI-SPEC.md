# Phase 21 — UI Design Contract

> Visual and interaction contract for leftover playground chrome cleanup. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is **not a new visual system**. Reuse the shipped Phase 20 Kobalte shell tokens, type scale, 44px hit targets, `#39D3C7` 2px / 4px focus ring, catalog previews, player chrome, Reset honesty, credits, and footer. ## Spacing Scale

Declared values (must be multiples of 4). Inherit live CSS custom properties in `web/src/app.css`. Do not add tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Demo-nav list and link gaps, status-dot gaps, definition-term spacing, preview-to-caption gap, focus-outline offset companion |
| sm | 8px | Demo-nav-link padding block, preview frame radius, toolbar/control-group internal gaps, footer row gaps, figure-to-caption gap |
| md | 16px | Sidebar/drawer padding, header padding, default control gaps, narrow-page padding, fallback-panel padding at ≤480px |
| lg | 24px | App-shell / player-panel / **fallback-panel** / footer padding and section gaps, desktop body column gap |
| xl | 32px | Player-main vertical gap on desktop |
| 2xl | 48px | Unused this phase; keep token for existing page-level history |
| 3xl | 64px | Unused this phase; keep token for existing page-level history |

Exceptions (layout constants, not new spacing-scale tokens):

- Play, Pause, Reset, Retry, Apply setting, scene actions, **fallback Open Dam Break**, Demos trigger, Close, GitHub source, and every native `<select>` keep a **44px** minimum block size.
- Desktop demo sidebar stays a **280px** column.
- Compact preview frame stays `max-block-size: 72px`.
- Current-demo marker stays the shipped **3px** inset start bar.
- One-pixel borders and a two-pixel focus outline are visual strokes, not layout spacing.
- Do not introduce 44px, 72px, 280px, or 3px as spacing-scale tokens.

`.fallback-panel` already shares player-panel spacing: `gap` and `padding` at `--space-lg` (24px), dropping to `--space-md` (16px) at `max-width: 480px`. Keep that. Do not invent a new fallback layout.

Source: `web/src/app.css` `--space-*`, `.fallback-panel`, `.product-control`; `20-UI-SPEC.md` Spacing Scale.

## Typography

Use exactly four public sizes and two weights. Inherit Phase 20. Do not add a fallback-only size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / caption / footer / credit / reset-hint / interaction instruction / Static preview | 14px | 600 labels and credit terms; 400 captions, footer body, reset-hint, Static preview, interaction instruction | 1.4 |
| Body / demo-nav title / control value / buttons / **fallback body** | 16px | 400 descriptions, body, and `.fallback-copy`; 600 demo-nav titles, control labels, and buttons | 1.5 |
| Section heading / scene title / drawer title / **fallback heading** | 20px | 600 | 1.3 |
| Page heading (`h1`) | 28px | 600 | 1.2 |

Do not introduce a display face, web font, all-caps paragraph text, or weights other than 400 and 600.

Pre-existing shell exception, not a new Phase 21 size: `.demo-nav-description` remains **13px / 400 / 1.4**. Keep that frozen shell rule. Do not restyle it. Do not apply 13px to fallback copy.

The site heading is the only `h1` (`liquidfun-rs`). The player, **unknown fallback**, or drawer title is the only heading at `h2`/Dialog.Title rank on a given view. Unknown fallback heading uses `h2#player-title`. Demo titles stay styled spans, not headings.

`.fallback-copy` stays **16px / 400 / 1.5 / `#A9B4C0`**. Fallback heading stays the existing `h2` rule (**20px / 600 / 1.3 / `#F4F7FA`**). Open Dam Break stays **16px / 600**.

Allow wrapping; never truncate, marquee, or shrink below this scale.

Source: `20-UI-SPEC.md` Typography, live `web/src/app.css` `h2` / `.fallback-copy` / `.product-control`.

### Unknown fallback markup (locked)

Use a no-prop component. Do not pass `kind`, `sceneTitle`, or `maybeRaw`.

```tsx
<section class="fallback-panel" aria-labelledby="player-title">
  <h2 id="player-title">Scene not found</h2>
  <p class="fallback-copy">
    This playground link does not match a known scene. Open Dam Break, or choose a demo from the navigation list.
  </p>
  <a class="product-control" href="#/scene/dam-break">Open Dam Break</a>
</section>
```

Do not interpolate the unknown token into heading, body, `aria-*`, or `href`. `routeIdentity` may still key on `unknown:${maybeRaw}` in App state; that string must not appear in the panel.

### Honesty lines that must not appear

Do not use: `Choose a scene`, `{title} is not ready yet`, `Ready`, `Not ready yet`, `live thumbnail`, nested catalog `Open`, `pigment chemistry`, `complete LiquidFun parity`, `Dispose session`, `LiquidFun Rust/WASM browser proof`, `Press Space to pause`, `demo card`, `catalog card`, `pick a demo from the scene cards`, or any claim that a catalog preview is a running simulation.

Use fixed application strings through text nodes. Do not insert raw exception text or `maybeRaw` with `innerHTML`.

## Unknown Fallback Interaction Contract

This is the only visitor-facing UI change in Phase 21.

| Condition | Render |
|-----------|--------|
| `#/scene/{approved-id}` for a ready catalog id | Shared player. Unchanged from Phase 20. |
| empty hash, `#/`, `#/scene`, `#/scene/` | **Not fallback.** `normalizeSceneRoute` history-replaces to `#/scene/dam-break` and plays Dam Break. Do not undo this. Parser `kind: "empty"` may remain for unit tests; it must not reach FallbackPanel. |
| unknown identifier (example: `#/scene/not-a-scene`) | Unknown fallback inside `<main class="playground-main">`. Heading `Scene not found`, locked body, `Open Dam Break`. |

Behavior:

- Fallback views keep `PlaygroundShell`, demo navigation, header, and footer visible.
- Do not construct a WASM world, show a loading spinner that implies a scene load, or leave a blank canvas.
- Hide Play / Pause / Reset / Retry, scene controls, canvas, figcaption, and credits.
- Do not set `aria-current="page"` on any demo-nav link.
- Activating `Open Dam Break` sets hash `#/scene/dam-break` and starts Dam Break in the shared player.
- Demo-nav links remain the alternate recovery path; they are unchanged.
- `:focus-visible` on Open Dam Break uses the existing global rule: **2px solid `#39D3C7` with 4px offset**. Do not add a second focus system.
- At `max-width: 480px`, Open Dam Break is full-width and keeps **44px** min block size, matching other `.product-control` links.
- No confirmation dialog. Open Dam Break is not destructive.

App wiring after cleanup:

- `Show` fallback is `<FallbackPanel />` with no props.
- Delete `fallbackProps` and `FallbackKind` / `FallbackPanelProps` unions that include `empty` and `not-ready`.
- If a not-ready catalog id were ever returned, still mount this unknown chrome rather than a blank canvas. Do not add new not-ready copy. All six shipped ids stay `ready: true`.

Source: `21-CONTEXT.md` D-04–D-06, `21-RESEARCH.md` Pattern 2, live `web/src/App.tsx` `Show` fallback, `web/e2e/player.spec.ts` unknown-hash test.
