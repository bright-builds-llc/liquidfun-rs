# Phase 19 — UI Design Contract

> Visual and interaction contract for canvas pointer polish, per-scene instruction copy, keyboard/focus completion, and narrow-width usability. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Desktop contract (≥721px viewport width):

## Viewport Contract

- The Canvas viewport is the primary focal point only after a ready scene has a drawn frame. Fallback views use the fallback heading and body as the focal point and must not show a blank canvas.
- Use a Canvas 2D viewport with a 16:9 CSS aspect ratio and `width: 100%`.
- Use an intrinsic design size of 960 by 540 CSS pixels. Scale backing-store dimensions by `min(devicePixelRatio, 2)` and redraw after size changes.
- Fit the shared Rust world bounds `(-6,-1)..(6,8)` inside the viewport with a 16px internal inset. Preserve aspect ratio and center the world; do not stretch physics coordinates.
- Invert the world y-axis only in the shared projection / unprojection pair. Browser code must not interpolate, integrate, or otherwise alter Rust positions, colors, or wheel angles.
- Convert pointer samples with the live CSS `getBoundingClientRect()` and the current camera. Never use `canvas.width` / backing-store pixels as physics coordinates.
- Resize must not rebuild the world. Reuse the last-frame redraw plus camera fit, then convert the next pointer sample through the updated CSS bounds.
- Clear to `#071018` for every frame. Draw particles first, then rigid segments, then rigid circles so boundaries remain legible.
- Draw each particle as a filled circle using Rust-provided position, radius, and color. Do not replace particles with DOM/Solid components, add trails, or blend Color Mixer hues in JavaScript.
- Draw rigid segments with a 2px `#94A3B8` stroke. Draw rigid circles with `#334155` fill and 2px `#CBD5E1` stroke. Water Wheel paddles are transformed segment lanes from Rust, not CSS-rotated DOM.
- Give the canvas `role="img"` and the accessible name `Live {Scene name} scene: Rust particles and rigid bodies.` Bind `aria-describedby` to the figcaption `id` that holds the interaction instruction. Include fallback text inside the element: `Canvas is required to display the {Scene name} scene.`
- The canvas is **not** a keyboard widget. Do not set `tabindex`. Do not add custom canvas keydown handlers.
- Keep status, controls, instructions, and credits in DOM text outside the canvas. Never rely on drawn text to communicate loading, pause, failure, reset, credits, or the gesture.
- Set `cursor: crosshair` on the canvas while a ready scene is Playing or Paused so the viewport reads as interactive. Use the default cursor while Loading or Failed.
- Do not draw a gesture HUD, crosshair overlay, aim line, or drag ghost in JavaScript.

Loading leaves the viewport cleared to its canvas color with the loading empty-state overlay. Playing and paused show the last drawn Rust frame. Failure preserves the last successfully drawn frame when one exists; otherwise it remains cleared with the error copy outside the canvas. Fallback views omit a live session and show the fallback copy instead of a cleared mystery canvas.

Source: `18-UI-SPEC.md` Viewport Contract, `19-CONTEXT.md` D-02, D-04, D-07, D-08, D-11; `19-RESEARCH.md` Pattern 1.

## Pointer Interaction Contract

This is the Phase 19 visual/interaction addition. Keep every Phase 18 labeled control. Pointer input is one extra live path into the same scene controllers.

### Shared pipeline

- Attach one Pointer Events listener set on the player canvas, not on catalog cards.
- On `pointerdown`, call `setPointerCapture`. Clear gesture state on `pointerup`, `pointercancel`, and `lostpointercapture`.
- Pause, Reset, Retry, scene change, leaving the player, and Solid cleanup must release capture and emit a WASM `cancel` so no stuck force, grabbed body, or captured pointer remains.
- Apply `touch-action: none` only on `canvas`. Do not set `touch-action: none` on `html`, `body`, `#root`, catalog, footer, or credits.
- Call `preventDefault` only on the canvas after capture. Catalog, footer, credits, and the rest of the page keep native scrolling and pinch-zoom.
- Ignore uncaptured `pointermove`. Do not listen for separate `mousedown` / `touchstart` stacks.
- Do not require `event.isTrusted`. Automated `pointercancel` must still clear the gesture.
- Each scene implements exactly one documented canvas gesture. Do not add camera pan, pinch, hover debug, or multi-touch editing.
- Physics stay native. Pointer input sends world x/y into the WASM session; JavaScript must not animate particle or body positions.

### Gesture map

| Scene | Gesture | Visual expectation | Labeled path still present |
|-------|---------|--------------------|----------------------------|
| Dam Break | Captured drag repositions the existing obstacle; release wakes it | Obstacle follows the pointer inside the basin; letterboxed clicks clamp to about `[-5.5, 5.5]` × `(0, 8)` and do not teleport outside the world | `Drop obstacle`, `Reset obstacle` |
| Fountain | Captured drag aims the stream from the nozzle toward the pointer | Stream direction updates while dragging; Aim angle `<select>` is not rewritten | `Aim angle` Left / Up / Right |
| Float or Sink | Pointer-down drops the selected body at the click’s world x, y = 6.0 | One drop per down; later downs add up to the existing four-body cap | `Body` + `Drop body` |
| Color Mixer | Captured drag stirs nearby particles through engine forces | Colors mix from contact, not from a JavaScript blend; lift or cancel stops the local force | `Stir speed` |
| Jelly Drop | Pointer-down pokes at the world location | Blob deforms at the poke; no JS position animation | `Poke jelly` |
| Water Wheel | Captured drag aims the jet from the fixed nozzle toward the pointer | Wheel still turns from native particle-body coupling; Jet strength still sets speed | `Jet strength`, `Emission` |

### Cancel and pause

- Cancel leaves Dam Break at the last set pose; it does not snap to Reset obstacle.
- Fountain keeps the last aimed direction.
- Float or Sink and Jelly Drop downs are one-shot; cancel after down is a no-op.
- Color Mixer clears the stored stir point so leftover force cannot continue.
- Water Wheel clears the aim override and reverts to the labeled default jet vector.
- Paused scenes may still accept a one-shot drop or poke, matching labeled actions that already present a paused frame. A captured drag must cancel if the visitor presses Pause scene.

### Verification chrome (not user-visible)

`main` may expose `data-last-pointer-kind` (`down` / `move` / `up` / `cancel`) and an incrementing `data-pointer-accepted` for Playwright. Do not render those attributes as on-page copy.

Source: `19-CONTEXT.md` D-01 through D-07; `19-RESEARCH.md` Patterns 2–4. Discretion defaults: Dam Break is captured drag; Water Wheel aims direction, not strength.

## State and Interaction Contract

| State | Visible treatment | Behavior |
|-------|-------------------|----------|
| Loading | `Loading {Scene name}…`; muted status; identity visible; loading overlay; Play/Pause/Reset, scene controls, and canvas gestures disabled; Retry hidden | Await generated initializer, construct the selected scene, validate a frame, and draw it before leaving this state |
| Playing | `Playing`; accent status dot; live viewport; Pause, Reset, scene controls, and canvas gestures enabled; Play disabled; Retry hidden | Advance the current session with Phase 17 ownership, hidden-tab, and catch-up caps |
| Paused | `Paused`; muted status; last frame retained; Play, Reset, scene controls, and one-shot canvas downs enabled; Pause disabled; Retry hidden | Freeze the world without disposing it. Do not step. Redraw on resize only. Cancel any in-flight drag/stir. Runtime control changes that do not recreate may still apply, then wait for Play to show motion |
| Failure | `{Scene name} failed`; destructive status and error copy; last frame retained when available; Retry and Reset enabled; Play/Pause, scene controls, and canvas gestures disabled | Stop the session and release pointer capture. Retry or Reset recreates the current scene from its documented initial state plus the last applied construction presets |
| Fallback | Fallback heading and body; no live session; `Open Dam Break` enabled; Play/Pause/Reset/Retry, scene controls, and canvas hidden | Do not construct a WASM world |

Playing is permitted only after WASM initialization, selected-scene construction, frame validation, and the first successful canvas draw. A compile-only or canned-motion state must never produce the playing copy.

Default after a successful load: start Playing so a visitor sees real Rust motion. If `prefers-reduced-motion: reduce` is active, draw the first frame and enter Paused instead.

Hidden-tab suspension is not a distinct visual state. If the document is hidden while Playing, pause stepping without changing the Playing label, and cancel any captured gesture; on resume, clear catch-up time and continue Playing. User-visible `Paused` is only for an explicit Pause scene action or the reduced-motion start.

The status text is an atomic polite live region. The fixed error sentence uses `role="alert"` only while failure is present. Do not announce frame counts, step indexes, or pointer kinds.

### Playback and keyboard

- Use native `<button type="button">` elements with the exact labels `Play scene`, `Pause scene`, `Reset scene`, and `Retry scene`.
- Enter and Space use native button, select, and link activation. Do not add custom keyboard handlers for those keys. Do not add a global Space-to-pause shortcut. Do not add canvas arrow-key aiming.
- Catalog Open links, playback, presets, Apply setting, and scene actions remain keyboard-operable.
- Show a 2px solid `#39D3C7` `:focus-visible` outline with a 4px outline offset on **buttons, selects, and in-page links**. Add `select:focus-visible` to the existing rule if it is missing. Never remove the browser focus indicator without this replacement.
- Hover may change fill only when enabled. Disabled treatment must not look clickable.
- Play starts or resumes stepping. Pause freezes the world without disposing it and cancels an in-flight canvas gesture. Reset disposes the current session and recreates the current scene from its documented initial state. Retry does the same recreate after failure.
- Do not show a confirmation dialog. Reset, Retry, and Apply setting release only transient local resources.
- Do not restore `Dispose session`.
- Hash navigation must not steal focus away from the player heading except when the visitor activates a catalog or fallback link.

### Scene controls

- Render each scene's two or three locked controls from catalog metadata. Do not invent a fourth labeled control because a canvas gesture exists.
- Recreating presets: `<label>` + native `<select>` + `Apply setting` button, with the construction reset hint visible before Apply setting. Changing the select does nothing until Apply setting.
- Runtime presets: `<label>` + native `<select>`; apply on `change` without a reset hint.
- Actions: native `<button type="button">` with the locked verb+noun label.
- After a recreating Apply setting, the player may pass through Loading and then return to Playing (or Paused when reduced motion is active). Cancel any captured pointer before the world is recreated.
- Obstacle drop/reset, Drop body, and Poke jelly do not recreate the world and do not show the reset hint.

### Catalog interaction

- Every shipped card `Open` link is keyboard-operable as a hash link.
- Visiting a shipped scene hash starts that scene. Visiting empty or unknown hashes must not start physics, show a spinner that implies a load, or silently redirect without the matching fallback copy.

Source: `19-CONTEXT.md` D-01, D-08, D-10, D-11; `18-UI-SPEC.md` State and Interaction Contract.

## Narrow-Viewport Acceptance

Phase 19 owns WEB-07. The 480px stack is no longer a containment-only preview.

- At viewport widths of 480px or less, use 16px page, card, and panel padding and 16px vertical gaps.
- Keep the page and panels at `min-width: 0`; no element may cause horizontal page scrolling at 320px viewport width.
- Catalog becomes one column. Cards, status metadata, scene controls, credits, and footer rows stack into one column.
- Keep the canvas at full available width and 16:9 on a ready scene. At a 320px viewport, the expected content canvas is at least 256px wide after page and panel padding.
- Make Play, Pause, Reset, Retry, Open, Apply setting, scene actions, fallback Open Dam Break, and selects full-width while retaining the 44px minimum block size.
- Interaction instructions wrap naturally under the canvas. Do not truncate, ellipsize, or hide them at narrow widths.
- Scene-control groups that share a row on desktop stack to one full-width column so a label, select, hint, and Apply setting never overflow.
- Allow heading, card titles, descriptions, status, fallback, error, credits, and footer copy to wrap naturally.
- A 375×812 Chromium pass must show: visible `#39D3C7` 2px / 4px focus rings on buttons, selects, and links; readable `#F4F7FA` / `#A9B4C0` on `#0B0F14` / `#151D28`; wrapping without horizontal page scroll; and native page scroll outside the canvas.
- After a window resize, the next canvas drag or tap must hit the intended world point. Do not rebuild the world on resize.
- Do not add a hamburger, orientation handling, breakpoint-specific physics, or a second scene set for mobile.

Source: `18-UI-SPEC.md` Narrow-Viewport Minimum, `19-CONTEXT.md` D-07, D-10, D-12.

## Motion and Accessibility Minimum

- Add no cosmetic animation, pulsing, shimmer, or transition. The physics scene is the only continuous motion. Catalog SVGs stay still.
- Do not flash the viewport or status. State changes are immediate and text-backed.
- `prefers-reduced-motion: reduce` starts the selected scene paused after the first drawn frame. The visitor can press Play scene. One-shot canvas drop/poke may still apply while paused.
- Maintain at least WCAG AA text contrast for declared text/surface pairs, including inverse text on accent-filled buttons and muted interaction instructions on the secondary panel.
- Preserve document zoom, text wrapping, and browser defaults. No keyboard trap. Do not make the document a touch trap.
- Construction reset is announced by visible hint text, not color alone. Playing versus paused is announced by status text, not the accent dot alone.
- Canvas remains `role="img"`; the keyboard path is labeled controls plus the figcaption reminder.
- Focus rings must appear on selects as well as buttons and links.

Source: `18-UI-SPEC.md` Motion and Accessibility Minimum, `19-CONTEXT.md` D-08, D-10, D-11.
