### Magnet marker **[UI-D81]**

The marker is a bar magnet drawn in the gravity frame, so it tilts with gravity (`GravityFrame` from `world.gravity()` inside `collect_segments`, the diver bubble precedent; no hard-coded −y, D-14). With `up = −g/|g|` and `across = (up.y, −up.x)`, centered on `magnet_position`:

| Part | Geometry | Segments | When |
|------|----------|----------|------|
| Bar outline | rectangle 0.8 m along `across` × 0.2 m along `up` | 4 | always |
| Pole divider | the bar's center line along `up`, full bar height | 1 | on only |
| Field ticks | three ticks along `up`, starting 0.04 m above the top face, each 0.16 m long, at `across` offsets −0.25, 0, +0.25 | 3 | on only |

- **On** (energized): outline + divider + ticks = 8 segments. **Off** (parked): outline only = 4 segments, at `MAGNET_REST`. On and off therefore differ by shape at a glance, as D-17 asks, with the one shared segment color.
- At rest the bar's top face is flush with the slab bottom (y = −0.25) and the ticks rise through the slab band, reading as the pull going up into the dish.
- If gravity is too small to define a frame (`GravityFrame::from_gravity` returns `None`), draw the bar axis-aligned (`up = (0, 1)`), outline only. This cannot happen with the shipped slider (2–80) and is a defensive branch.
- Frame budget: dish loops (≤ 16) + marker (≤ 8), far under the 512-segment cap; circle cap (48) untouched.
- The marker is world content, not HUD chrome: no `data-hud-obstacle`, no DOM element.
- The segment list changes when the magnet moves or toggles, so the static segment layer repaints on those frames, as it already does for moving scenes. With the magnet still, the content is stable.

| Pointer up / cancel (identical) | magnet off, parked at `MAGNET_REST` under the dish |
