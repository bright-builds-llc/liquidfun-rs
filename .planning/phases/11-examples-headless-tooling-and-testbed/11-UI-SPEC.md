# Phase 11 — UI Design Contract

> Visual and interaction contract for the optional LiquidFun scenario testbed. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

The visual testbed is a passive adapter over the renderer-neutral scenario catalog, run-session controller, canonical checkpoints, and semantic comparison model. It may submit typed controller commands and render owned semantic snapshots; it must not own physics rules, advance simulation from render frames, reinterpret comparison policy, read private storage, or make screenshots authoritative compatibility evidence. This boundary is locked by `11-CONTEXT.md` D-06 through D-20.

______________________________________________________________________

## Design System

| Property | Value |
| --- | --- |
| Tool | Manual private desktop-tool UI; no web component system |
| Preset | Not applicable |
| Component library | Macroquad 0.4.15 immediate-mode UI only if the post-headless capability spike passes; otherwise the documented `winit`/`wgpu`/`egui` fallback |
| Icon library | None; use simple 16px renderer-owned vector icons paired with text or accessible names |
| Font | Platform system sans; platform system monospace only for hashes, semantic paths, numeric values, and provenance |

No React, Next.js, Vite, Tailwind, or `components.json` exists, so the shadcn initialization and registry gates are not applicable. No renderer dependency may enter `liquidfun`, the default workspace member, or any publishable crate. The testbed package is unpublished and non-default. These choices come from `11-CONTEXT.md` D-17 through D-22 and `.planning/research/STACK.md`.

### Component Inventory

| Component | Contract |
| --- | --- |
| App bar | Project identity, active scenario title, controller state, comparison backend state, and an About/Provenance affordance |
| Scenario browser | Searchable, keyboard-navigable catalog grouped by reviewed category; each row shows display title, stable slug, version, seed support, and Rust/oracle/visual eligibility |
| Simulation viewport | Renders only renderer-neutral debug primitives and semantic diff records; owns camera transform and selection presentation only |
| Run control strip | `Run Scenario`, `Pause`, `Resume`, `Step Once`, `Restart`, and `Capture Checkpoint`; state and enabledness mirror the controller |
| Settings editor | Validated timestep, velocity-iteration, position-iteration, and particle-iteration fields; invalid input never reaches the controller |
| Overlay controls | Independent labeled toggles for shapes, joints, contacts, contact normals, particle contacts, broad phase, centers of mass, AABBs, statistics, and profiles |
| Inspector | Tabs for Run, Observe, Differences, and Provenance; every row exposes stable semantic identity or path rather than a private slot/index |
| Difference list | Virtualized bounded list keyed by semantic path with state, policy, Rust value, oracle value, and `Focus` action |
| Status toast | Non-authoritative acknowledgement for capture, screenshot, copy, or recoverable error; never the only presentation of an error |
| About/Provenance panel | Source, license truth, Peter Ryszkiewicz/OpenLinks attribution, version, short commit, target, profile, toolchain, oracle identity, and build provenance |

Buttons use explicit verbs and visible labels. An icon-only control is permitted only for universally understood viewport actions such as zoom reset, must have a 44px target, accessible name, hover/focus tooltip, and keyboard equivalent.

## Spacing Scale

Declared values are the only spacing values:

| Token | Value | Usage |
| --- | --- | --- |
| xs | 4px | Icon-to-label gaps, dense metadata separation |
| sm | 8px | Compact control groups, table-cell inset |
| md | 16px | Default panel inset, form-field gap |
| lg | 24px | Inspector sections and empty-state inset |
| xl | 32px | Major panel separation |
| 2xl | 48px | App-bar height and compact major rhythm |
| 3xl | 64px | Bottom control strip height and large empty-state rhythm |

Exceptions: interactive targets have a 44px minimum width and height; 1px borders and 2px focus rings are strokes, not layout spacing. Border radii are 4px for fields and 8px for panels. No pill-shaped containers except compact status badges.

### Density Rules

- Use 16px panel padding and 8px gaps for the standard desktop layout.
- Use 8px cell padding in dense metric and difference tables; preserve a 44px row target when the row is actionable.
- Keep related control groups within 8px and separate unrelated groups by 16px.
- Never reduce text, focus targets, or hit areas to fit more diagnostics; collapse secondary panels instead.

## Typography

Use exactly four sizes and two weights across the testbed:

| Role | Size | Weight | Line Height |
| --- | --- | --- | --- |
| Label and metadata | 12px | 400 | 1.333 |
| Body and controls | 14px | 400 | 1.5 |
| Section heading | 18px | 600 | 1.333 |
| Display and scenario title | 24px | 600 | 1.167 |

- The only weights are regular 400 and semibold 600. Do not use bold 700.
- Use tabular numerals for timestep, iteration counts, entity counts, timings, seeds, and differences.
- Use monospace at the same declared 12px or 14px sizes for stable slugs, semantic paths, hashes, commits, exact bits, and provenance. Long values truncate visually with an ellipsis but remain available through focus/hover and `Copy`.
- Use sentence case for headings, buttons, tabs, fields, and status labels. Avoid all caps except compact fixed protocol/evidence identifiers such as `D0` and `D1`.

## Color

The first loaded experience is dark. The 60/30/10 allocation applies to visible surfaces and primary emphasis:

| Role | Value | Usage |
| --- | --- | --- |
| Dominant (60%) | `#0D1117` | Window background, viewport background, app bar |
| Secondary (30%) | `#161B22` | Scenario rail, inspector, control strip, cards, menus |
| Accent (10%) | `#58A6FF` | Primary CTA, selected scenario/tab, keyboard focus ring, active scrubber, selected semantic primitive |
| Destructive | `#F85149` | Physics mismatch/error state and genuinely destructive actions only |

Accent is reserved for the primary CTA, current selection, focused control, active timeline position, and selected semantic primitive. It is not a generic border, paragraph, decoration, or every-interactive-element color.

### Supporting Palette

| Token | Value | Contract |
| --- | --- | --- |
| Primary text | `#F0F6FC` | Headings and high-priority values on dominant or secondary surfaces |
| Secondary text | `#B1BAC4` | Labels, helper text, and inactive metadata; never disabled to illegibility |
| Muted text | `#8B949E` | Timestamps and tertiary metadata only |
| Border | `#30363D` | Panel and field separation |
| Hover surface | `#21262D` | Row and button hover without changing selection |
| Success / exact match | `#3FB950` | Exact semantic match and completed capture |
| Policy-qualified difference | `#D29922` | Numeric difference accepted by a named policy; always labeled `Within policy` |
| Rust-only | `#FF8C42` | Rust-only observation and solid Rust overlay |
| Oracle-only | `#A371F7` | Oracle-only observation and dashed oracle overlay |
| Informational | `#39C5CF` | Broad-phase and non-error diagnostic geometry |

All normal text must meet WCAG 2.2 AA contrast: at least 4.5:1 for 12–18px text and 3:1 for large text, icons, focus indicators, and meaningful geometry. State must never be conveyed by hue alone:

- Exact match: green check plus `Exact match`.
- Within-policy difference: amber diamond plus policy name.
- Rust-only: orange `R` marker and solid geometry.
- Oracle-only: purple `O` marker and dashed geometry.
- Mismatch/error: red cross, persistent message, and a 2px halo around focused geometry.
- Unavailable: neutral outlined circle plus literal `Unavailable`; never blank, `0`, or a guessed value.

### Debug and Difference Layers

- Default debug geometry uses `#8B949E` at 1px; selected geometry uses the accent at 2px.
- Rigid contacts are 4px amber points; normals are amber lines with visible arrowheads.
- Particle contacts are 3px informational diamonds; preserve particle color data without relying on it as UI state.
- Broad-phase AABBs use informational 1px lines at 70% opacity.
- In overlay comparison mode, matching primitives fade to 35% opacity, Rust geometry is solid orange, oracle geometry is dashed purple, and the focused mismatch gains a red halo and semantic-path label.
- In side-by-side mode, both viewports use the same camera transform and scale; a camera change updates both without submitting a controller command.

## Layout Contract

### Standard Desktop Layout

At 1280px wide and above:

- 48px app bar across the top.
- 280px scenario browser on the left.
- Fluid simulation viewport in the center with a minimum 480px content width.
- 360px inspector on the right.
- 64px run control strip below the viewport and inspector, not below the scenario rail.
- A compact status line inside the app bar shows `Running`, `Paused`, `Stepping`, `Resolving`, `Comparing`, `Error`, or `Unavailable` with text and icon.

The viewport receives the largest share of remaining area. Metrics belong in the inspector, not as permanent floating cards over simulation geometry. Temporary viewport labels may identify the focused primitive or mismatch and must avoid the current cursor/selection when possible.

### Responsive Window Behavior

| Window width | Required behavior |
| --- | --- |
| `>= 1280px` | Five-region layout above; inspector and scenario browser both visible |
| `960–1279px` | Scenario browser is 240px; inspector becomes a 360px right drawer opened by its active tab |
| `720–959px` | Viewport fills the window below the app bar; scenario browser and inspector are mutually exclusive modal drawers; control strip wraps into two 44px rows |
| `< 720px` | Preserve the viewport and run controls; open catalog/settings/diff as full-window sheets and show `Compact window — panels open one at a time` once per session |

Minimum supported logical window is 640×480. Below that, do not shrink text or targets; show `Window too small` with `Resize to at least 640 × 480` while retaining the Close/About affordances. Resizing, DPI changes, and panel collapse must not change controller state, checkpoint identity, camera world coordinates, or selection identity. Panel scroll positions may remain local presentation state.

### Difference Presentation

- Default to overlay comparison when both backends are present.
- Offer `Overlay` and `Side by side` as a two-option segmented control; switching modes changes presentation only.
- The Difference list sorts in canonical semantic-path order supplied by the comparison model. The UI must not re-sort by magnitude or screen position unless the user explicitly selects a presentation sort; canonical order remains available and clearly labeled.
- Selecting a row focuses the corresponding stable primitive key in all visible viewports and opens bounded Rust/oracle values and the named numeric policy.
- `Next difference` and `Previous difference` wrap only within the current filtered list and announce the new ordinal, for example `Difference 3 of 12`.

## Interaction Contract

### Controller Semantics

| Command | Visible result | Required invariant |
| --- | --- | --- |
| Run/Resume | Status becomes `Running`; pause control becomes primary | Logical ticks are owned by the controller, never by render refresh |
| Pause | Status becomes `Paused` | No logical tick and no fabricated checkpoint |
| Step Once | Status briefly becomes `Stepping`, then `Paused` | Exactly one logical tick executes and the session remains paused |
| Restart | Rebuilds step zero from the same resolved bytes and validated settings | Current world is destroyed; run identity remains tied to the same resolved content |
| Capture Checkpoint | Adds one checkpoint at the controller-supplied action/step ordinal | Capture identity never uses frame number, wall time, or UI event time |
| Change settings | Shows parsed value or inline error before Apply | Invalid or out-of-range values never reach simulation; applying settings uses the controller's validated restart contract |
| Select scenario | Resolves the selected stable slug/version and displays exact run identity | Display title is never used as catalog identity |

Controller pause and a scenario action that pauses an upstream particle system are visually and semantically distinct. Label the former `Session paused`; label the latter in the action/event log as `Particle system pause action`.

### Keyboard

Global shortcuts are active only when a text/numeric field is not editing:

| Shortcut | Action |
| --- | --- |
| `Space` | Pause or resume the session |
| `Right Arrow` | Step once; if running, pause first and then execute one tick |
| `R` | Restart from step zero |
| `C` | Capture deterministic checkpoint |
| `/` | Focus scenario search |
| `F` | Focus the first or current difference |
| `[` / `]` | Previous / next difference |
| `1` | Toggle contacts |
| `2` | Toggle particle contacts |
| `3` | Toggle broad-phase data |
| `4` | Toggle profiles/statistics |
| `Home` | Reset camera to scenario bounds |
| `?` | Open shortcut help |
| `Escape` | Close the topmost drawer/dialog or clear viewport focus |

`Tab` and `Shift+Tab` traverse visible controls in visual order. `Enter` activates the focused control or selects a scenario. Focus is never trapped outside modal drawers; opening a drawer moves focus to its heading/first control, closing returns focus to the invoker. Scenario-specific keys must be declared by the typed scenario action map, displayed in Help, and routed through the controller rather than mutating the world directly.

### Mouse and Trackpad

- Primary click selects a semantic primitive or activates a control.
- Wheel/pinch zooms the camera around the pointer; clamp to a useful declared renderer range and show the zoom percentage.
- Middle-button drag or `Shift` + primary drag pans the camera.
- Double-clicking empty viewport space resets the camera to scenario bounds.
- Hover may reveal a tooltip after 400ms but must not be required to discover identity or state.
- Camera, hover, tooltip, panel, and screenshot interactions submit no simulation commands and create no checkpoints.

### Settings Fields

- Timestep is displayed in seconds with exact accepted value available in the detail view; iteration controls are base-10 integers.
- On blur or Enter, parse and validate. Keep the previous accepted value when invalid.
- Show one inline message directly under the field, such as `Enter a finite timestep greater than 0` or `Enter an integer from 1 to 1024`.
- `Apply & Restart` is the only settings commit action. It remains disabled until at least one valid field differs from the active settings.

## Copywriting Contract

Use concise operational language. Always distinguish authoritative semantic capture from diagnostic screenshots and wall-clock timing.

| Element | Copy |
| --- | --- |
| Primary CTA | `Run Scenario` |
| Empty state heading | `Select a scenario` |
| Empty state body | `Choose a reviewed catalog scenario to resolve its run plan and inspect it headlessly or visually.` |
| Empty differences heading | `No differences at this checkpoint` |
| Empty differences body | `Rust and oracle observations match under the selected policies.` |
| Empty capture heading | `No checkpoint captured` |
| Empty capture body | `Run or step the scenario, then capture a deterministic semantic checkpoint.` |
| Loading scenario | `Resolving scenario…` |
| Loading oracle | `Starting the pinned oracle…` |
| Loading comparison | `Comparing semantic checkpoints…` |
| Validation error | `This setting is not valid. Correct the highlighted value and try again.` |
| Scenario error | `Scenario could not start. Review the run details, correct the issue, and try again.` |
| Oracle unavailable | `Oracle unavailable. Continue with Rust-only diagnostics or configure the pinned oracle.` |
| Capture success | `Checkpoint captured at step {step}.` |
| Screenshot clarification | `Screenshot saved. Screenshots are diagnostic and do not prove compatibility.` |
| Build fallback | `Unavailable` |
| Destructive confirmation | None; Phase 11 defines no irreversible data deletion. `Restart` is confirmation-free because it deterministically reconstructs the same resolved plan, and its label is always `Restart from step 0` in tooltips/help. |

Error panels contain a one-sentence problem, a specific recovery action, and a collapsed `Details` region with bounded technical context. Never show raw private indices, C++ pointers, unbounded stderr, or stack traces in primary UI copy. Preserve full bounded diagnostic artifacts through the existing failure-bundle workflow.

## State Contract

| State | Presentation | Available actions |
| --- | --- | --- |
| No selection | Empty viewport illustration made from neutral debug primitives; no simulated data | Search/select scenario, open About |
| Resolving | Inline progress indicator beside the scenario title; prior viewport dims and is marked `Previous run` | Cancel selection if supported; no run/step/capture |
| Ready paused | Step 0 shown, `Paused` status, Run is primary | Run, Step Once, Restart, settings, capture if checkpoint 0 is declared |
| Running | Resume replaced by Pause; live logical step shown | Pause, capture, camera/overlay controls |
| Stepping | One brief controller transition; controls prevent duplicate step submission | Camera/overlay controls only until result returns |
| Comparing | Existing checkpoint stays visible with progress in Difference tab | Camera/overlay controls; cancel only if backend contract supports it |
| Exact match | Green check and `Exact match` with checkpoint identity | Continue, capture, inspect values |
| Within policy | Amber diamond and `Within policy` with named policy | Inspect difference, focus geometry |
| Physics mismatch | Persistent red status and first semantic path | Focus, previous/next, capture failure bundle |
| Rust-only / oracle-only | Orange `R` or purple `O`, never framed as a match | Inspect missing-side context |
| Recoverable error | Inline panel retains last valid semantic checkpoint and controller state | Retry or correct field; copy details |
| Harness failure | Distinct `Harness failure` heading; never `Physics mismatch` | Open bounded details, retry/configure backend |
| Provenance unavailable | Literal `Unavailable` per missing field | Copy available summary; open source/about |

Progress indicators must not imply deterministic progress from wall-clock duration. Use an indeterminate indicator for process startup/comparison unless the controller supplies a real bounded item count. Respect reduced-motion preferences when the selected framework exposes them; otherwise keep animation subtle, under 200ms for transitions, and never make motion the only state signal.

## Provenance, Source, and License Chrome

The app bar provides a compact `About & provenance` affordance. Its panel must include:

- `liquidfun-rs` and the active application version, or `Version Unavailable`.
- Short Rust commit and linked full public GitHub commit when available; otherwise `Commit Unavailable`.
- Build profile, target triple, Rust toolchain, adapter/protocol version, and build/run identity; each missing field is `Unavailable`.
- Oracle revision, compiler, preset, and evidence tier when the oracle participates; otherwise `Oracle Unavailable`.
- Recognizable source/GitHub icon and `View source` linking to `https://github.com/bright-builds-llc/liquidfun-rs`.
- `MIT-licensed open-source Rust project` linked to the repository license, plus `LiquidFun/Box2D provenance and notices` linked to the checked-in upstream/notice documentation. Do not imply that all upstream material is governed only by the Rust crate license.
- `By Peter Ryszkiewicz` and an `OpenLinks` link to `https://openlinks.us/`; show the OpenLinks mark only when it fits without displacing run controls or project identity.

External links use the platform's safe external-open mechanism. If the selected framework cannot open a link reliably, provide a visible copyable URL instead of hiding the disclosure. Provenance remains visible in normal product chrome and is not confined to logs or README files.

## Accessibility Contract

- Every control has a visible label or accessible name, keyboard equivalent where applicable, and a 44px minimum target.
- Focus uses a persistent 2px accent ring with at least 3:1 contrast and is never removed because a mouse was used.
- Tables and lists expose a clear focused row, current selection, and position/count text. Virtualization must preserve keyboard order and selection identity.
- State uses icon/shape, text, and color together. Diff geometry additionally uses solid/dashed strokes and `R`/`O` labels.
- Tooltips supplement visible labels and never contain the only recovery instruction.
- Do not flash debug geometry or state more than three times per second. Disable decorative animation when reduced motion is available.
- Numeric values, semantic paths, and provenance are selectable/copyable from the inspector.
- When a mismatch is focused, announce its kind, ordinal, semantic path, policy, Rust value presence, and oracle value presence in one concise status sentence.

## Implementation Guardrails

- Build and verify the headless catalog, controller, checkpoint, and comparison model before implementing the visual package.
- The Macroquad spike must demonstrate readable rigid contacts, particle contacts, broad-phase overlays, profiles, synchronized diff modes, deterministic semantic capture, diagnostic screenshots, controls, keyboard focus, text density, DPI/resizing, and required desktop behavior. Record a specific failure before selecting the heavier fallback.
- UI components consume controller state and semantic records as immutable input. They may retain only presentation state: camera, open panel, scroll, focus, local filters, and screenshot options.
- The visual adapter must not translate scenario definitions into backend-specific physics calls, infer comparison policy, create stable identity from screen position, or use render order as semantic order.
- Screenshots, frame rate, and measured durations are labeled diagnostic. Canonical checkpoints, stable semantic paths, and D0–D3 evidence remain authoritative.
- `liquidfun` remains the only default publishable crate and gains no renderer, windowing, game-engine, C++, protocol, or testbed dependency or default feature.
