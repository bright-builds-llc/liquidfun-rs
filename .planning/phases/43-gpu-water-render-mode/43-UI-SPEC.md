### Water look palette (canvas pixels, `web/src/render/water-uniforms.ts`)

| Element | Value | Rule |
|---------|-------|------|
| Background outside the water | `#071018` (`uBackground`, same as `CANVAS_COLOR` and shaded blob) | pixels where the field edge is 0 are exactly this color, so Water, shaded blob and canvas fallback share one backdrop |
| Refraction backdrop raster | fill `#071018`, static segments stroked `#94A3B8` (`BASIN_STROKE_COLOR`) at the 2D stroke width | water-owned raster (Research Pattern 3); dynamic rigid bodies are not in it |
| Procedural backdrop (no stable raster yet) | `#071018` plus horizontal stripes `+0.035` per channel, 24 stripes per field height | so refraction still reads before the static raster exists |
| Water body hue | each particle's own RGB (`sum.rgb / sum.a`) | multi-material and colored scenes keep their colors (D-06) |
| Thin water (edges, sprays) | mostly the refracted backdrop multiplied by `mix(1, particleColor, 0.5)` | clear water lets walls show through, tinted |
| Deep water (pools, packed interior) | approaches the particle color | Beer-Lambert: `transmit = exp(-WATER_ABSORPTION * thickness)` |
| Density shading (checkbox on) | particle color multiplied by the existing `DENSITY_SHADE_START 1.15 / END 2.8 / FLOOR 0.73` curve before tinting | the existing "Density shading" control stays meaningful in Water **[UI-D43]** |
| Specular highlight | additive white, `WATER_SPECULAR_STRENGTH * pow(max(dot(n, h), 0), WATER_SHININESS)` | small bright glints on curved surfaces; final color clamped to `[0, 1]` |
| Foam | blend toward `#F4F7FA` (theme foreground, near-white) by `foam * WATER_FOAM_MAX` | white spray on fast water; capped below a flat white so overlay keylines stay readable **[UI-D44]** |

### Starting constants (Claude's discretion per CONTEXT; tune by eye, record final values in the SUMMARY)

| Constant | Starting value | Meaning |
|----------|----------------|---------|
| `WATER_FOAM_SPEED_LOW` | 3.0 m/s | foam starts (smoothstep lower edge, world speed) |
| `WATER_FOAM_SPEED_HIGH` | 7.5 m/s | foam saturates (smoothstep upper edge) |
| `WATER_FOAM_MAX` | 0.85 | strongest foam blend toward `#F4F7FA` |
| `WATER_REFRACTION_PX` | 10 CSS px | largest backdrop offset at the steepest field gradient, converted to field UV with the capped DPR |
| `WATER_NORMAL_SCALE` | 6.0 | field-gradient to normal steepness |
| `WATER_ABSORPTION` | 0.9 per kernel-sum unit | interior near 1.6 transmits about 24%; a lone-edge sum near 0.5 transmits about 64% |
| `WATER_SHININESS` | 48 | Blinn-Phong exponent |
| `WATER_SPECULAR_STRENGTH` | 0.55 | highlight intensity |
| `WATER_LIGHT_DIR` | `normalize(vec3(-0.35, 0.55, 0.76))` | fixed light from the upper left, in clip-space orientation (y up) |
| Edge | `smoothstep(0.42, 0.62, sum.a)` | identical to shaded blob, so the water outline does not shift when the view falls back to shaded blob **[UI-D45]** |

Tuning targets: dam-break, fountain and the first plain-water puzzle level. Pass criteria by eye: slow pooled water reads clear and tinted with visible highlights and no foam; fountain jets and the dam-break front show white spray; the cup, target line and meter remain readable over foam. Tiny-particle scenes may show little foam (Research Pitfall 9); that is accepted.

The water look has **no time uniform**: no ripples, shimmer or animated noise. Every pixel is a function of the current frame only, so a paused view is a still image and repaints are identical **[UI-D46]**.

## Layer Stack (D-04, D-16)

Bottom to top, identical for scene and puzzle routes:

| Layer | Element | Content in Water mode |
|-------|---------|-----------------------|
| 0 | `canvas.particle-surface` (`z-index: 0`, `data-active="true"`) | `#071018` background, refracted backdrop inside the water, water body, highlights, foam |
| 1 | `canvas.scene-canvas` (`z-index: 1`), **transparent** | static walls (crisp, on top of their refracted copy), rigid bodies, circles, and on puzzle routes the cup, fill meter, target line, tools, labels and placement halos, all with their existing colors and keylines |
| 2 | DOM chrome | HUD, scale legend, drawer trigger, all unchanged |

CSS edit (Research Pitfall 2), the only stylesheet change in this phase:

```
canvas.scene-canvas[data-particle-surface="webgl"],
canvas.scene-canvas[data-particle-surface="webgl-water"] {
  background: transparent;
}
```

Use the explicit two-value list rather than a prefix selector, so a future surface name cannot become transparent by accident **[UI-D47]**. When the drawn surface is `"canvas"` (fallback), the 2D canvas paints its own opaque `#071018` fill in `drawRenderFrame`, so a transparent CSS background never exposes a blank particle canvas.

The water layer never draws on the 2D canvas, and the 2D canvas never samples the water. Overlay readability over foam relies on the existing dark keylines (`SHADOW_STROKE rgba(7,16,24,0.65)` in `glass-cup.ts`, `KEYLINE_STROKE rgba(7,16,24,0.80)` in `puzzle-tools.ts`); no overlay color changes.

## Component Contracts

### Particles select, both pickers (D-01, D-03, D-05)

Option order inside the existing "Surface" `<optgroup>`, top to bottom: "Soft blob", "Contour", "Shaded blob", **"Water"**. No new group, no separator.

| State | `<option value>` | Text (= accessible name) | `disabled` |
|-------|------------------|--------------------------|------------|
| Available (probe passed) | `water` | "Water" | no |
| Unavailable (probe failed) | `water` | "Water (unavailable)" | yes |

- Both pickers render through `RenderModeOptions` with the same `waterAvailable` value, so the scene drawer, the puzzle drawer and the puzzle form-factor control row never disagree.
- `waterAvailable` comes from the per-page cached capability probe, read synchronously once when the playground session is created (Research Pattern 6). There is no "checking" state and the option text never changes during a page session **[UI-D48]**.
- **Stored "water" on an unavailable device:** the select keeps `value="water"` and shows "Water (unavailable)" as its current value; the view draws through the D-12 chain (shaded blob, else canvas). The stored preference is not rewritten. Choosing any other mode persists that mode as today; the disabled option cannot be re-chosen **[UI-D49]**. This is an honest display: the select says Water is unavailable while the view shows the fallback.
- **Runtime fallback on a capable device** (context lost, MRT incomplete at resize, shader failure): the option stays "Water", enabled. The fallback is visible only as the drawn look and the `data-drawn-surface` attribute (Research Open Question 3) **[UI-D50]**.
- Selecting Water: `changeRenderMode("water")` persists to `liquidfun.render-mode.v1` and repaints the held frame immediately. A paused frame captured before the switch has no speed lane, so it shows Water with zero foam until the next step (Research Pitfall 8). No re-step for rendering.
- Selecting any other mode turns the speed lane off on the next capture; the look switches on the same repaint.

### Controls shown with Water

Water is a surface mode (`usesParticleStride("water") === false`), so the scene options sheet shows exactly what it shows for Shaded blob:

| Control | Shown for Water | Note |
|---------|-----------------|------|
| Stroke-width slider | no | wireframe-only, unchanged |
| Rendered-particle cap | no | stride modes only, unchanged |
| "Surface modes draw every particle." note | yes | existing copy, unchanged |
| "Density shading" checkbox | yes | applies to the water body color (UI-D43) |
| Debug toggle and other existing controls | unchanged | |

Puzzle routes keep the Particles select as their only display option (UI-D7); no density control is added there.

### Fallback presentation (D-12, D-14, D-15)

| Situation | What the player sees | `data-drawn-surface` on `canvas.scene-canvas` |
|-----------|----------------------|-----------------------------------------------|
| Water selected, available, context healthy | water look | `webgl-water` |
| Water selected, water pass unavailable (probe failed or MRT/shader failure), float targets OK | shaded blob look, same outline | `webgl` |
| Water selected, no float render target or no WebGL2 | canvas soft blob (`paintMetaball`) on the opaque 2D canvas | `canvas` |
| Context lost (any time, including paused) | the held frame repaints immediately as canvas soft blob | `canvas` |
| Context restored | GPU resources rebuild and the held frame repaints as water | `webgl-water` |
| Shaded blob selected | unchanged from today | `webgl` (or `canvas` on fallback) |
| Any other mode | unchanged from today | `canvas` |

Rules:

- Never present a blank or black frame: every frame and every held-frame repaint ends with one of the three surfaces covering the particles.
- No notice, toast, live announcement or HUD change accompanies a fallback or recovery **[UI-D51]**. The physics, overlays, HUD and controls behave identically in all three surfaces.
- No transition or cross-fade between surfaces; the switch happens on the next repaint.
- Test-facing attributes (not styled, never rendered as text): `data-drawn-surface="webgl-water" | "webgl" | "canvas"` and `data-speed-lane="present" | "absent"` on `canvas.scene-canvas`. The existing `data-particle-surface` keeps meaning the **requested** surface and keeps driving CSS (Research Assumption A1) **[UI-D52]**.

### Exports (D-17)

SVG export, README SVG/WebP and demo media look exactly as today while Water is selected: `svgRenderMode("water") === svgRenderMode("shaded-blob") === "solid"`; README plans stay `"wireframe"`, demo media stays `"circle-wireframe"`. No export control shows Water-specific copy.

## Accessibility Contract

- **Names:** the select's accessible name stays "Particles" (existing label). The new option's name is its text: "Water" or "Water (unavailable)". `getByRole("option", { name: "Water", exact: true })` finds one option per open picker on a capable device; `getByRole("option", { name: "Water (unavailable)" })` finds one disabled option per picker when unavailable.
- **Disabled reason:** carried in the option text itself, so it is readable by sight and by screen reader without a separate description.
- **Focus ring:** existing `select:focus-visible` outline (`2px solid #4DA3FF`, offset 4px).
- **Non-color cues:** material identity stays in each particle's own hue (UI-D42); foam and highlights are decorative and carry no game information. The cup fill, target line and meter keep their own shapes, colors and keylines above the water.
- **Contrast:** overlays keep dark keylines over the brightest foam (`#F4F7FA * 0.85` blend); foam never reaches flat `#FFFFFF` (UI-D44).
- **Reduced motion:** the water look adds no animation of its own (UI-D46). `prefers-reduced-motion` needs no special case. Fallback switches are instant, not animated.
- **Live regions:** none added.
- **Text safety:** every rendered string is a TS constant; no `innerHTML`.
