# Plan 03-02: World Objects, Destruction Cascades, and Associations

<objective>
Build the minimal non-solver world/object graph needed to prove typed ownership, upstream-shaped destruction cascades, invalidation, owned destruction evidence, and safe consumer associations.
</objective>

<threat_model>
- Forged, stale, destroyed, wrong-kind, and cross-world handles must be rejected before any adjacency or arena mutation occurs.
- A partial cascade must not leave dangling fixture, joint, group, or particle-system associations; validation happens once and the mutation order is centralized.
- Destruction event collection and association cleanup must be bounded by actual destroyed objects, preserve occurrence order, and avoid unbounded retained queues.
- Expected invalid input, capacity exhaustion, and cleanup of missing keys must not panic or poison world state.
</threat_model>
