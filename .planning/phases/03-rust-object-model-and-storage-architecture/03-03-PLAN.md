# Plan 03-03: Restricted Hooks, Owned Events, Deferred Commands, and Poisoning

<objective>
Prove the callback and mutation envelope without implementing a solver: transient contact views, narrow synchronous directives, bounded owned reporting, post-unlock typed commands, and explicit panic poisoning.
</objective>

<threat_model>
- Hook code must not retain transient contacts, forge mutable world access, or smuggle internal references into owned events or commands.
- Commands may contain stale, destroyed, wrong-kind, or cross-world handles by application time and must be rejected individually without resolving reused slots.
- Hook-generated command/event growth must have reviewed finite limits and explicit overflow errors rather than unbounded queues or allocation.
- A panicking hook must not leave the lock set, apply queued mutations, or allow a partially stepped world to masquerade as healthy; poison state must gate later operations.
</threat_model>
