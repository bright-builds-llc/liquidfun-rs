# Phase 17 — UI Design Contract

> Visual and interaction contract for the shared SolidJS player, honest early catalog, and public GitHub Pages chrome. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | none |
| Font | system UI stack: `ui-sans-serif, system-ui, sans-serif` |

Phase 17 evolves the Phase 16 semantic HTML plus one page-scoped CSS file. `17-CONTEXT.md` D-09 locks this as a deliberate thin-slice exception to the managed SolidJS/MysticUI preference so Pages delivery is not blocked by a new design-system adoption. ## Spacing Scale

Declared values (must be multiples of 4). Reuse the Phase 16 CSS custom properties:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-dot gaps, definition-term spacing, catalog ready/not-ready chip padding |
| sm | 8px | Inline metadata, heading stacks, toolbar button padding, footer row gaps |
| md | 16px | Default control, catalog item, and narrow-page spacing |
| lg | 24px | Player-panel sections, catalog-to-player gap, desktop content gaps |
| xl | 32px | Desktop page padding and header-to-catalog gap |
| 2xl | 48px | Desktop top and bottom page padding |
| 3xl | 64px | Maximum page-level vertical margin on tall screens |

Exceptions: Play, Pause, Reset, Retry, and Open Dam Break each have a 44px minimum block size. One-pixel borders and a two-pixel focus outline are visual strokes, not layout spacing. Do not introduce 44px as a spacing-scale token.

Source: `16-UI-SPEC.md` Spacing Scale, evolved for product controls. Default 8-point scale confirmed in auto mode.

## Typography

Use exactly four sizes and two weights across the public site.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / caption / footer / chip | 14px | 600 labels and chips; 400 captions and footer body | 1.4 |
| Body | 16px | 400 | 1.5 |
| Section heading / scene title | 20px | 600 | 1.3 |
| Page heading | 28px | 600 | 1.2 |

Do not introduce a display face, web font, all-caps paragraph text, or weights other than 400 and 600. The site heading is the only `h1`. The player or fallback heading is the only `h2` on a given view. Provenance values may use tabular numerals. Allow wrapping; never truncate, marquee, or shrink below this scale.

Source: `16-UI-SPEC.md` Typography. Confirmed default in auto mode.

## Color

Reuse the Phase 16 dark playground tokens. The public site remains dark-default.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` | Page background and surrounding negative space |
| Secondary (30%) | `#151D28` | Catalog strip, player panel, fallback panel, footer, canvas frame |
| Accent (10%) | `#39D3C7` | Playing indicator, current-scene marker, Play and Retry fills, keyboard focus ring, Rust-provided particle highlights |
| Destructive | `#F87171` | Failure status and error copy only |
| Primary text | `#F4F7FA` | Headings, status, catalog names, button text on secondary fills |
| Inverse text | `#0B0F14` | Text on accent-filled Play and Retry buttons |
| Muted text | `#A9B4C0` | Summary, captions, not-ready labels, provenance labels, paused status |
| Border | `#2A3441` | Panels, catalog items, canvas boundary, secondary buttons |
| Canvas | `#071018` | Viewport clear color |
| Rigid geometry | `#CBD5E1` | Basin and dynamic rigid-body outline |

Accent reserved for:

1. the playing status dot;
1. the current Dam Break catalog marker;
1. Play and Retry button fills and their hover state;
1. `:focus-visible` outlines on buttons and in-page links;
1. particle colors supplied by the Rust frame.

Accent is not used for headings, panel borders, body copy, Pause, Reset, not-ready chips, footer text, or decorative gradients.

The page follows a visual 60/30/10 hierarchy: most pixels remain the dominant background; catalog, player, and footer provide the secondary layer; accent occupies only state, current-scene, primary-action, and simulation details. Status meaning must always be present in text; color is supplementary.

### Control fills

| Control | Background | Border | Text | Hover |
|---------|------------|--------|------|-------|

Reset is not destructive. It recreates a transient local simulation and must not use the Phase 16 Dispose red treatment. No gradients, glow effects, or translucent glass surfaces.

## Page Structure and Layout

Use this semantic order on every view:

1. `<main aria-labelledby="site-title">`
1. A `<header>` containing the `h1` and one-sentence summary.
1. A `<nav aria-labelledby="scene-nav-title">` containing the `Scenes` label and the six approved names in this exact order: Dam Break, Fountain, Float or Sink, Color Mixer, Jelly Drop, Water Wheel.
1. A `<section aria-labelledby="player-title">` for the shared player or fallback. This is the only runtime surface.
1. A `<footer>` containing source, FOSS, maintainer, and provenance chrome.

Desktop contract:

- Center one content column with `max-width: 960px`.
- Give the page 32px inline padding, 48px top/bottom padding, and 32px between header and catalog.
- Place a 24px gap between catalog and player, and 32px between player and footer.
- Catalog is a wrapping horizontal list, not a six-card gallery. Each item is one scene name plus a 14px Ready or Not ready yet chip. Dam Break is a hash link. The five later names may be hash links to their stable IDs, but they must not look playable: muted name, muted chip, no accent marker.
- Give catalog, player, and footer a one-pixel border, 12px radius, and 24px padding on the secondary surface.
- Place scene title, status, and runtime identity in a wrapping row with 16px gaps.
- Place the viewport 24px below that row and the control toolbar 24px below the caption.
- Place Play, Pause, and Reset in one wrapping row with 8px gaps. Show Retry only in failure, first in that row.
- Keep buttons content-width on desktop; do not stretch them into a full-width bar.

Do not add a marketing hero, sidebar, card grid, preview thumbnails, search, scene-parameter controls, or per-scene credit lists.

Source: `17-CONTEXT.md` D-02, D-03, D-07, D-10. Layout numbers evolved from `16-UI-SPEC.md`.

## Viewport Contract

- The Canvas viewport is the primary focal point only on the Dam Break player after a frame exists. Fallback views use the fallback heading and body as the focal point and must not show a blank canvas.
- Use a Canvas 2D viewport with a 16:9 CSS aspect ratio and `width: 100%`.
- Use an intrinsic design size of 960 by 540 CSS pixels. Scale backing-store dimensions by `min(devicePixelRatio, 2)` and redraw after size changes.
- Fit the fixed Rust world bounds inside the viewport with a 16px internal inset. Preserve aspect ratio and center the world; do not stretch physics coordinates.
- Invert the world y-axis only in the pure projection function. Browser code must not interpolate, integrate, or otherwise alter Rust positions.
- Clear to `#071018` for every frame. Draw particles first, then basin segments and the dynamic rigid circle so rigid boundaries remain legible.
- Draw each particle as a filled circle using Rust-provided position, radius, and color. Do not replace particles with DOM/Solid components or add trails.
- Draw basin segments with a 2px `#94A3B8` stroke. Draw the dynamic circle with `#334155` fill and 2px `#CBD5E1` stroke.
- The canvas is not interactive or focusable in this phase. Set no pointer handlers; preserve ordinary page scrolling and default touch behavior. Pointer polish is Phase 19.
- Give the canvas `role="img"` and the accessible name `Live Dam Break scene: Rust particles and a rigid body in a basin.` Include fallback text inside the element: `Canvas is required to display the Dam Break scene.`
- Keep status and identity in DOM text outside the canvas. Never rely on drawn text to communicate loading, pause, failure, or fallback.

Loading leaves the viewport cleared to its canvas color with the loading empty-state overlay. Playing and paused show the last drawn Rust frame. Failure preserves the last successfully drawn frame when one exists; otherwise it remains cleared with the error copy outside the canvas. Fallback views omit a live session and show the fallback copy instead of a cleared mystery canvas.

Source: `16-UI-SPEC.md` Viewport Contract, `17-CONTEXT.md` D-07, D-13. Auto-mode default to keep Phase 16 drawing rules.

## State and Interaction Contract

| State | Visible treatment | Behavior |
|-------|-------------------|----------|
| Loading | `Loading Dam Break…`; muted status; identity visible; loading overlay; Play/Pause/Reset disabled; Retry hidden | Await generated initializer, construct Dam Break, validate a frame, and draw it before leaving this state |
| Playing | `Playing`; accent status dot; live viewport; Pause and Reset enabled; Play disabled; Retry hidden | Advance the current session with the Phase 16 ownership rules and the Phase 17 hidden-tab / catch-up caps |
| Paused | `Paused`; muted status; last frame retained; Play and Reset enabled; Pause disabled; Retry hidden | Freeze the world without disposing it. Do not step. Redraw on resize only |
| Failure | `Dam Break failed`; destructive status and error copy; last frame retained when available; Retry and Reset enabled; Play/Pause disabled | Stop the session. Retry or Reset recreates Dam Break from the documented initial state |
| Fallback | Fallback heading and body; no live session; `Open Dam Break` enabled; Play/Pause/Reset/Retry hidden | Do not construct a WASM world. Provide a working path to `#/scene/dam-break` |

Playing is permitted only after WASM initialization, Dam Break construction, frame validation, and the first successful canvas draw. A compile-only or canned-motion state must never produce the playing copy.

Default after a successful Dam Break load: start Playing so a visitor sees real Rust motion. If `prefers-reduced-motion: reduce` is active, draw the first frame and enter Paused instead.

Hidden-tab suspension is not a distinct visual state. If the document is hidden while Playing, pause stepping without changing the Playing label; on resume, clear catch-up time and continue Playing. User-visible `Paused` is only for an explicit Pause scene action or the reduced-motion start.

The status text is an atomic polite live region. The fixed error sentence uses `role="alert"` only while failure is present. Do not announce frame counts or step indexes.

### Playback controls

- Use native `<button type="button">` elements with the exact labels `Play scene`, `Pause scene`, `Reset scene`, and `Retry scene`.
- Enter and Space use native button activation. Do not add custom keyboard handlers for those keys.
- Show a 2px solid `#39D3C7` `:focus-visible` outline with a 4px outline offset on buttons and in-page links. Never remove the browser focus indicator without this replacement.
- Hover may change fill only when enabled. Disabled treatment must not look clickable.
- Play starts or resumes stepping. Pause freezes the world without disposing it. Reset disposes the current session and recreates Dam Break from its documented initial state. Retry does the same recreate after failure.
- Do not show a confirmation dialog. Reset and Retry release only transient local resources.
- Do not restore `Dispose session`.

### Catalog interaction

- Dam Break is always keyboard-operable as a hash link.
- Visiting a known not-ready hash must not start physics, show a spinner that implies a load, or silently redirect without the not-ready copy.
- Unknown and empty identifiers use the matching fallback copy, never a blank app or a hard 404-looking empty page.

Source: `17-CONTEXT.md` D-07, D-08, D-11, D-12, Claude's Discretion.

## Narrow-Viewport Minimum

This phase requires containment, not Phase 19 responsive acceptance.

- At viewport widths of 480px or less, use 16px page and panel padding and 16px vertical gaps.
- Keep the page and panels at `min-width: 0`; no element may cause horizontal page scrolling at 320px viewport width.
- Stack catalog items, status metadata, and footer rows into one column.
- Keep the canvas at full available width and 16:9 on Dam Break. At a 320px viewport, the expected content canvas is at least 256px wide after page and panel padding.
- Make Play, Pause, Reset, Retry, and Open Dam Break full-width while retaining the 44px minimum block size.
- Allow heading, catalog names, status, fallback, error, and footer copy to wrap naturally.
- Do not add a hamburger, orientation handling, touch simulation controls, or breakpoint-specific scene behavior.

Source: `16-UI-SPEC.md` Narrow-Viewport Minimum. Phase 19 owns WEB-07 polish.

## Motion and Accessibility Minimum

- Add no cosmetic animation, pulsing, shimmer, or transition. The physics scene is the only continuous motion.
- Do not flash the viewport or status. State changes are immediate and text-backed.
- `prefers-reduced-motion: reduce` starts Dam Break paused after the first drawn frame. The visitor can press Play scene.
- Maintain at least WCAG AA text contrast for declared text/surface pairs, including inverse text on accent-filled buttons.
- Preserve document zoom, text wrapping, and browser defaults. No keyboard trap. Hash navigation must not steal focus away from the player heading except when the user activates a catalog or fallback link.
- Not-ready status is text, not color alone.

Source: `16-UI-SPEC.md` Motion and Accessibility Minimum, updated now that playback exists.
